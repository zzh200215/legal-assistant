## 二、高优先级问题详情与优化方案

### P0-1 新注册用户组织归属断裂（首访任务全部卡死）

- **问题描述**：注册成功 → 自动登录 → 工作台表面正常（摘要卡片、空案件列表）→ 点"新建案件"填写提交 → 弹出"不是该组织成员"，案件创建失败。同样影响咨询、审查、文书等所有组织上下文操作。
- **出现场景**：`Login.vue` 注册页签自助注册（文案"首次使用可注册账号，注册后自动登录"）→ 落地 `/legal-workspace` → 任意创建操作。
- **用户影响**：首次用户无法完成任何核心任务；错误文案"不是该组织成员"对刚注册的用户不可理解（"我刚注册成功，凭什么不是成员？"），且界面无任何出路（无"创建组织/等待邀请"引导），用户只能放弃。
- **判断依据**（实测）：
  1. API 实测：`GET /api/legal/overview` 对新用户返回 `organization_id: null`；
  2. [LegalWorkspace.vue L269](../frontend/src/views/LegalWorkspace.vue)：`currentOrgId = computed(() => overviewQuery.data.value?.organization_id || 1)` 回退到组织 1；
  3. API 实测：`POST /api/legal/orgs/1/cases` 返回 `401 NOT_ORG_MEMBER "不是该组织成员"`（[auth_api.py 注册端点注释](../app/api/auth/auth_api.py)：自注册"不接受组织归属"）；
  4. 前端 [CaseCreateDialog.vue L62](../frontend/src/components/legal/CaseCreateDialog.vue) 弹出后端 detail 原文，无上下文解释。

**优化方案**：
- **优化目标**：注册后 30 秒内能完成第一个案件创建；错误永远附带出路。
- **具体调整**（双管齐下）：
  1. **后端**：`POST /auth/register` 成功时自动创建"个人组织"（名称=用户姓名/用户名 + "的工作台"），并将用户加入为 admin——`organization_id` 永不为 null，开箱即用（个人产品定位下最短路径）；
  2. **前端兜底**：`currentOrgId` 为 null 时不再回退 `|| 1`，WorkbenchHome 顶部渲染引导条："你还未加入任何组织。个人组织创建中/请联系管理员邀请"，并禁用创建类按钮（disabled + tooltip）而非放行后报错；
  3. **文案**：NOT_ORG_MEMBER 映射为"你暂无该组织的访问权限。请联系组织管理员将你加入团队，或切换到自己有权限的组织。"
- **涉及页面/组件**：`app/api/auth/auth_api.py`、`app/api/legal/legal_case_api.py`（错误 detail）、`frontend/src/views/LegalWorkspace.vue`、`frontend/src/components/legal/WorkbenchHome.vue`、`frontend/src/api/errors.js`。
- **预期效果**：注册→建案件路径 100% 打通；即使后端策略调整，用户也永远看到带出路的引导而非裸错误。

### P1-2 首次登录零引导 + onboarding 死路由

- **问题描述**：注册/登录后直接落空工作台，无欢迎、无引导；专门的引导页 `LegalOnboarding.vue`（角色选择 + 三步引导，质量不错）挂在 `/legal-onboarding`，但登录后 `router.push('/')` → 重定向 `/legal-workspace`，导航栏无"开始使用"入口，全库无跳转逻辑——**页面存在但用户永远发现不了**。
- **出现场景**：注册后落地；任意时刻想找"怎么上手"的入口（不存在）。
- **用户影响**：首次用户面对"今天先处理什么？"的空看板不知从何开始；onboarding 里设计的"创建案件→合同审查→发布门户"路径用户看不到；且 onboarding 第一步就会撞上 P0-1。
- **判断依据**（实测+静态）：`router.js` L24 `/ → /legal-workspace`；`App.vue` L155 注释称"`/` 会重定向到 `/legal-onboarding`"与实际行为不符（注释即意图未实现的证据）；直接输入 URL 访问 `/legal-onboarding` 页面正常渲染（角色单选/步骤条/保存进度/进入工作台）。
- **补充观察**：onboarding 的"保存进度"按钮对无组织用户大概率同样 401（未实测，需修复 P0-1 后回归）。

**优化方案**：
- **优化目标**：90% 新用户在首次会话内完成第一个任务。
- **具体调整**：
  1. 用户表增加 `onboarded_at` 标记（迁移 0094）；登录后若为空且无案件 → 跳 `/legal-onboarding`；
  2. onboarding"进入工作台"与"保存进度"均写该标记；侧栏底部增加"使用指南"常驻入口（复用 onboarding 页）；
  3. onboarding 三步引导内容与真实权限/数据状态联动（无案件时步骤 1 高亮"新建案件"按钮）。
- **涉及页面/组件**：`alembic/versions/`（新迁移）、`app/api/auth/auth_api.py`（登录返回 onboarded）、`frontend/src/views/Login.vue`、`frontend/src/views/LegalOnboarding.vue`、`frontend/src/App.vue`。
- **预期效果**：新用户有明确的"第一步"；onboarding 从死代码变为首访主路径。

### P1-3 "全 0 工作台"失败假象（随 P0-1 联动修复）

- **问题描述**：无组织用户的 overview 请求成功但返回空数据、cases 等请求 401 被各组件 catch 吞掉，工作台呈现"0 案件、0 咨询、0 审查"的**正常假象**。用户误以为新账号本来就空，直到创建操作才碰壁。
- **判断依据**：[WorkbenchHome.vue L74-84](../frontend/src/components/legal/WorkbenchHome.vue) `catch { reviewItems.value = [] }` 静默；摘要数字全部 `|| 0` 兜底；实测 overview 200 + cases 401 并存。
- **优化方案**：随 P0-1 的 org 修复后此问题自然消失；但需建立规范——**区分"空数据"与"请求失败"两种空态**（失败态显示"加载失败 [重试]"，不与"暂无数据"混用）。列入中期 M-13 统一错误处理。

### P1-4 客户门户 OTP 死胡同错误页

- **问题描述**：SMTP 未配置/故障时，客户打开门户链接 → 自动发送验证码失败 → 页面仅显示"门户验证码邮件暂不可用"空状态，**无重试按钮、无解释、无联系方式**。客户（非专业用户，且大概率在手机上）完全茫然，只能打电话给律师。
- **出现场景**：实测 `POST /api/legal/portal/{token}/send-otp` 失败（本地无 SMTP）→ [LegalPortal.vue](../frontend/src/views/LegalPortal.vue) `errorState = "门户验证码邮件暂不可用"` → `el-empty` 终态展示。
- **用户影响**：SMTP 故障期间门户功能全废且用户无自救手段；律师侧无感知（没有告警）。
- **判断依据**：运行时实测（619px 视口，门户 URL 直开）；`LegalPortal.vue` errorState 分支无任何操作按钮。

**优化方案**：
- **优化目标**：OTP 失败可自恢复或可求助；律师可感知故障。
- **具体调整**：
  1. 错误态增加"重新发送验证码"按钮（冷却 30s）+ 次级文案"若多次失败，请联系你的律师（{律所名称}）"——律所名称已在门户 brand 数据中；
  2. 后端 send-otp 失败写运维告警事件（接入既有 `dispatch_operational_alerts` beat 任务）；
  3. 邮箱不可达与链接无效两种 errorState 分开文案（当前混在一个 errorState）。
- **涉及页面/组件**：`frontend/src/views/LegalPortal.vue`、`app/api/legal/portal_access.py`（或对应 send-otp 路由）、`app/tasks/`（告警任务）。
- **预期效果**：SMTP 瞬时故障用户可自恢复；持续故障 10 分钟内律师收到告警。

### P1-5 权限可见性错误：可见但不可用

- **问题描述**：普通成员（demo_lawyer，legal_role=member）在案件"客户门户"tab 能看到并点击"创建门户链接"，提交后才收到"仅组织管理员或审核律师可管理案件"。
- **出现场景**：实测 demo_lawyer 点击创建 → 401 detail 弹出；换 demo_reviewer 成功（权限分层本身正确）。
- **用户影响**：挫败感 + 对系统权限规则的不信任；同类问题模式（先放行后拒绝）可能存在于其他角色敏感操作。
- **判断依据**：`portal_links_access.py` `_require_case_manager` 校验；前端 `LegalPortalTab.vue` 按钮无角色条件渲染/disabled。

**优化方案**：
- **优化目标**：不可用操作不出现或明示原因。
- **具体调整**：`LegalPortalTab.vue` 接收当前用户 `legal_role`，非 manager 时"创建门户链接"按钮 `disabled` + tooltip"需要管理员或审核律师权限"；同模式排查审核队列批量分配（ReviewBulkAssignment）等写操作入口。
- **涉及组件**：`LegalPortalTab.vue`、`useAuth/user store`、（排查）`SystemTasksTab.vue` 等。
- **预期效果**：权限错误提示归零；角色边界可预期。

## 四、快速优化清单（低成本，1-3 天内可落地）

2. **登录失败文案三态拆分**：`errors.js` INVALID_CREDENTIALS 按 `error.code` 细分（INVALID_CREDENTIALS / ACCOUNT_LOCKED / ACCOUNT_DISABLED），锁定带剩余时间。

4. **空状态就地 CTA**：WorkbenchHome"还没有案件"块内加"新建案件"按钮（emit 已存在，纯模板改动）。
5. **LLM 阶段性文案**：咨询/审查/文书提交按钮 loading 期间轮换阶段提示（setInterval 文案切换，约 20 行）。
6. **忘记密码入口**：登录表单下加链接 + 接入既有 forgot-password API 的最小弹窗流程。

## 五、中期优化建议（产品/设计/研发协作）

1. **错误与状态处理体系**（对应 M-13/M-11/P1-3）：制定三态规范（加载/空/失败）组件 `<StateBlock>`；errors.js 错误码→中文映射全覆盖并接入 ElMessage 统一出口；新增表单必须 :rules；PR 模板加"错误态截图"检查项。涉及：前端架构规范 + 全量页面渐进改造。
2. **首次用户旅程**（对应 P0-1/P1-2）：注册即建个人组织 + onboarding 首登接入 + 首任务 checklist（建案件→提一次咨询→查看结果，进度存 localStorage）+ 完成后通知庆祝反馈。涉及：后端迁移、路由守卫、onboarding 重构。

4. **客户门户移动端专项**（对应 M-10/P1-4）：门户是唯一客户直接触达的界面，按移动优先重做（375px 基准），含 OTP、进度时间线、文书下载、账单四块。

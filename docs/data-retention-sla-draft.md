# 数据保留与删除策略 SLA 草案（#95，2026-09-15）

> 合规 §5.3 首项（compliance-dossier §7.1）：用户注销后数据处置流程。产品未实现，
> 本文冻结**策略基线**（分类/期限/流程/技术可行性），供 POC 审计问答与后续开发立项。

## 1. 数据分类与保留期限

| 类别 | 示例 | 保留期限（草案） | 依据 |
|---|---|---|---|
| A. 账户基础数据 | 用户名/邮箱/角色 | 注销后 30 天删除（冷却期内可撤销注销） | 网信办《个人信息保护法》47 条删除义务 |
| B. 法律业务数据 | 咨询/审查/文书/案件/合同 | **5 年**（诉讼时效跨期 + 律所执业义务，与律所档案惯例对齐） | 《律师法》执业档案要求、民法典 188 条时效 |
| C. 计费/发票数据 | 账单/支付/退款记录 | **10 年**（税务凭证） | 《税收征管法》52 条账簿凭证保管 |
| D. 操作/安全日志 | 审计/操作/门户访问日志 | 180 天（活跃），归档 2 年 | 等保 2.0 日志留存 ≥180 天 |
| E. LLM 观测 | token_usage/llm 日志 | 90 天（成本与质量分析），可配置缩短 | 最小化原则 |
| F. 密钥/凭据 | 加密密钥/API key | 随账号主体删除即作废 | 最小化原则 |

## 2. 删除流程（目标设计）

```
用户发起注销 → 30 天冷却期（可撤销）
  ├─ 冷却期内：账号置 disabled，业务数据保留可恢复
  ├─ 冷却期结束：
  │   ├─ A 类：立即物理删除（用户基础表行）
  │   ├─ D/E/F 类：按各自期限自然过期（日志为追加写，做掩码/停用而非删除）
  │   └─ B/C 类：标记 deleted（逻辑删除 + 主体匿名化：user_id 置 NULL、客户姓名/联系方式加密字段抹除），
  │              物理保留至 5/10 年期限后由归档任务清除
  └─ 出口：注销确认回执（邮件）+ 数据处置说明
```

## 3. 技术可行性核对（当前代码）

| 项 | 现状 | 缺口 |
|---|---|---|
| 注销入口/API | 无（用户仅可登出） | 需新增 DELETE /api/users/me + 冷却期状态机 |
| 业务数据逻辑删除 | 部分（legal_* 有 status/soft 字段） | 需统一 deleted 标记 + 主体匿名化任务 |
| 敏感字段抹除 | EncryptedText 支持空值覆盖（enc:v2 轮换先例） | 需删除任务按主体批量置空 |
| 日志掩码 | 追加写，不做删除 | 需要按 user_id 掩码策略（日志中 user_id 关联） |
| 归档清除任务 | 备份任务已有（02:00） | 需新增 retention purge 任务（按期限清理） |
| 注销回执 | 邮件模板已有（outbound_email 体系） | 需模板 + 触发 |

## 4. SLA 承诺（POC 审计问答口径）

1. 注销冷却期：30 天可撤销；
2. A 类数据：冷却期结束后 24h 内删除；
3. B/C 类数据：主体匿名化 ≤24h；物理清除 ≤5/10 年期满后 30 天；
4. 审计应答时限：数据主体行权请求（查询/删除/更正）≤15 天（PIPL 要求）；
5. 供应商（LLM）侧：请求不落盘承诺依赖 dashscope 默认策略，正式商用前出书面确认。

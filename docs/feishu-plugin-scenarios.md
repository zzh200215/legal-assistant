# 飞书插件场景池（M-5，试点期收集）

> 用途：10 月上架飞书插件时带真实案例。试点期从访谈/反馈问卷持续补充，
> 每场景记录「触发上下文 → 用户动作 → 期望产出」，插件设计直接复用。

## A. 已在产品验证的场景（来自 demo/演示与主工作流，2026-08-04 整理）

1. **群内即时法律咨询**：律师在飞书群被客户问"公司拖欠工资三个月怎么办" → 转发给插件 → 返回分类/风险/法条引用/待补充事实卡片（对齐 /api/legal/consultations）。
2. **合同风险初筛**：客户在群发合同文件 → 插件读取文件 → 返回风险条款清单（类型/等级/原文摘录/修改建议）→ 律师再决定是否深度审查。
3. **劳动仲裁申请书生成**：律师简述案情（工作年限/解除时间/月薪）→ 插件生成申请书草稿（缺失字段【待补充】标注）→ 律师补全后导出。
4. **咨询→审查→文书流转**：一次咨询结论卡片上带"进入合同审查/生成文书"按钮，插件端保留同一案件上下文（对齐 U-3 案件闭环）。
5. **法条核对**：律师引用某法条 → 插件返回条款原文 + 效力状态 + 修订版本（对齐 AI-4 引用核验，试点期验证需求强度）。

## B. 试点期待验证场景（访谈问题清单）

6. **待办与期限提醒**：审查结果中的日期（合同期限/付款日）自动转飞书日程提醒——律师是否愿意把案件期限交给工具？（潜在北极星周边场景）
7. **客户门户轻触达**：通过飞书给客户发文书/查进度，替代登录门户——验证"门户锁定"叙事在 IM 时代的替代性。
8. **多合同批量对比**：两份合同版本差异自动高亮（对齐多文档对比）——律所是否批量审合同？
9. **审核决策回填**：律师在飞书卡片上"通过/退回"决策直接回写审核队列（对齐 AI-2 回流）——降低回流成本。
10. **私域知识库问答**：律所把历史胜诉文书/模板传插件 → 新案引用所内先例。

## C. 收集机制（试点第 1 周起）

- 每周周报附 1 个场景问题（#52 数据包已含 NPS/退出问卷基线，场景并入问卷）。
- 记录格式：`触发上下文 / 用户动作 / 期望产出 / 使用频率`，达到 3 次提及即进入插件 P0 范围。
- 同步至：本文件 + 12 月商业化阶段 M-5 任务输入。

## D. 优先级初判（待数据修正）

- P0（立项即做）：1、2、3 —— 都是"律师被客户打断"的高频痛点，工作流锁定价值最高。
- P1：4、6、9 —— 依赖试点证明"案件闭环"留存价值。
- P2：5、7、8、10 —— 差异化/长尾，试点数据出来再定。

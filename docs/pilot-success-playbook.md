# 试点成功机制（M-2）

适用：10 家律所封闭内测（2026-08 启动）。目标不是「把功能演示一遍」，而是**让每家所在一周内跑通一个完整办案闭环，并留下可量化的验证数据**。

配套材料：系统运行/灾备见 `pilot-runbook.md`；本文件是运营侧的动作脚本。

---

## 1. 招募话术

### 群发/私聊版（首句即钩子）

> 律智检：AI 帮你 3 分钟出劳动仲裁申请书、5 分钟审完一份合同。8 月免费内测，仅 10 家所。AI 结论可逐条核对法条原文和效力状态，高风险自动进律师审核，不直接外发。感兴趣的话，30 秒给您看个例子。

### 深聊版（回答「凭什么信你」）

- **信任**：每个 AI 结论都带置信度 + 可点击核对的引用（法条标题/条款/效力状态/版本），不是空口结论。
- **把关**：高风险事项强制走人工审核队列，通过/退回/转线下由律师决定；我们只做辅助。
- **闭环**：咨询 → 合同审查 → 文书草稿 → 律师审核 → 客户门户交付，一条路跑通，不切系统。
- **现在**：内测免费，团队版正式价 ¥999/月；参与内测的所优先享有上线优惠与专属支持。

### 招募门槛（筛掉不合适的，避免数据污染）

- 有真实案源的独立律师或 3-10 人小所（真实数据才能验证 AI 质量）。
- 主力场景在劳动仲裁 / 民间借贷 / 普通合同审查范围内（产品主战场）。
- 愿意每周配合填一次反馈问卷、让 AI 结果走人工审核队列。

## 2. 30 秒 Demo 脚本

场景锁定**劳动仲裁**（最优场景之一），三步讲完：

1. **咨询**（10s）：现场输入「公司辞退我，工作 3 年，没给经济补偿金」。结果页显示：分类/风险等级/置信度/逐条可核对的引用 + 待补充事实（缺少劳动关系起止时间等）。
2. **审核**（10s）：点「提交律师审核」，高风险自动进审核队列 —— 强调「AI 不直接出正式结论，律师把关」。
3. **文书 + 交付**（10s）：同一案件一键生成《劳动争议仲裁申请书》，缺失字段自动标【待补充】；导出或走客户门户交付。

收尾一句：「您今天的咨询结论，明天就会沉淀成评测用例，让这套系统越用越准。」

---

## 3. 试点目标：每人 7 天做满一个工作流

「完成度」按**可验证动作**计，不按「用了没有」。每家所的每位律师，7 天内：

| 目标动作 | 数量 | 验证口径（后台可查） |
|---|---|---|
| 完成首次角色引导，建立 ≥1 个案件 | ≥1 | 引导页进度 + legal_cases |
| 法律咨询（三线任选） | ≥3 | legal_consultations |
| 其中至少 1 次**提交律师审核** | ≥1 | status=needs_lawyer_review |
| 合同审查 | ≥2 | legal_contract_reviews |
| 文书草稿 | ≥2 | legal_drafts |
| 走通「咨询 → 审查/文书 → 审核」单案件闭环 | ≥1 | 同一 case_id 下有咨询+审查或文书 |
| AI 输出反馈（👍/👎 + 原因） | ≥5 | 反馈闭环 tab |

第 1-2 天熟悉系统；第 3-5 天做满上述动作；第 6-7 天体验客户门户 + 计费 + 填退出问卷。

## 4. 周报口径（每周五发给每家所）

数据全部来自已上线的管理端看板，不另做埋点：

1. **漏斗**：注册 → 首次咨询 → 首次审查 → 首次文书 → 首次审核通过 → 升级付费，每跳转化率 + 注册→首次咨询平均激活时长（System.vue「用户漏斗」tab）。
2. **反馈闭环**：正/负反馈数、负反馈原因分布、处理率（System.vue「反馈闭环」tab）。
3. **AI-2 回流**：本周新增律师审核决策评测用例数（`python -B scripts/export_review_feedback.py` 的 exported 数量）。
4. **成本**：本周咨询/审查/文书单次成本（llm-billing stats，核对毛利为正）。
5. **目标完成率**：各所完成「7 天目标」的律师占比。

## 5. 退出问卷（试点结束，10 分钟）

核心是验证两个假设：**「信任三件套」是否被认可**、**「合同审查是不是留存之王」**。

### A. NPS
> 您向同行推荐律智检的可能性（0-10 分）？______

### B. 信任三件套（单选各一）
1. AI 结果的**置信度数字**：可信 / 无感 / 不可信
2. **可点击核对的引用**（法条+条款+效力状态）：高频使用，必看 / 偶尔看 / 从不看
3. **明确下一步**（提交审核/导出/门户）：清晰有用 / 无感 / 找不到入口

### C. 业务价值
4. 三个功能按价值排序：法律咨询 / 合同审查 / 文书草稿（____ > ____ > ____）
5. 提交律师审核后，您最想要什么？____
6. 哪个环节最卡、最想砍掉？____

### D. 付费意愿
7. 团队版 ¥999/月（咨询 5000 次/月、审查 2000、文书 2000）：
   - 已打算续费 / 需要再试一个月 / 定价偏高 / 不会用

### E. 开放反馈
8. 最希望下个版本加的 1-2 个功能：____
9. 一句话总结试用感受：____

问卷结果回收后与漏斗/反馈/AI-2 数据合并，产出《试点验证报告》（回答「哪些假设被验证、哪些被证伪」），作为商业化与 AI-3/AI-4/AI-6 的输入。

## 6. 试点期间禁做（避免污染数据）

- 不向试点用户开放支付、电子签署、开放 API（半成品开关保持关闭）。
- 不让用户把 AI 结论直接作为正式法律意见外发；高风险必须走审核。
- 不要求试点所提供脱敏法律数据以外的任何敏感数据；备份/密钥管理见 `pilot-runbook.md`。

---

## 7. 销售话术：用 NPS/留存数据说话（12 月商业化前固化）

> 作用：把试点验证数据转成企业 POC 谈判的「证据链」。数据口径与仪表盘一致（北极星/留存/NPS 来自漏斗与问卷回收）。

### 7.1 对外可引用的指标口径（达标值）

| 指标 | 定义 | 达标口径 |
|---|---|---|
| 北极星活跃律师 | 周内发生 ≥1 次核心动作（咨询/审查/文书/审核）的律师数 | >0（当前基线 0） |
| 7 日留存 | 注册后第 7 天仍有核心动作的用户占比 | 记录并持续优化 |
| 30 日留存 | 注册后第 30 天仍活跃占比 | 同上 |
| NPS | 试点退出问卷 0-10 分 → 推荐者% - 贬损者% | ≥40 |
| 审核回流密度 | 每周产生的人工审核决策条数（AI-2 数据源） | 持续上升 |

> 说明：POC 谈判阶段如实引用已回收到数据，未达标指标按「试点进行中，数据持续增长」口径，不虚报。

### 7.2 三大话术要点（对应 M-4「合规+工作流锁定」）

1. **合规叙事**：数据全程加密（AES-256-GCM）+ 出站 PII 脱敏 + 双轨审计日志 + 等保二级自评材料齐备——直接回答案件信息安全疑虑（出示 compliance-dossier 与自评）。
2. **留存叙事**：合同审查为留存核心（试点验证假设）；AI-2 审核回流让模型越用越准，替代内部 Excel/共享盘工作流。
3. **成本叙事**：单次咨询≈0.012 元、单次审查全流程≈0.10-0.15 元（M-1 核算）；999 元/月团队版上限 5000 次，单位成本远低于人工初筛。

### 7.3 应对客户质疑（Q&A）

- **「AI 结论能直接当意见用吗？」**：不直接外发，高风险进律师审核；可逐条核对法条原文与效力状态。
- **「数据安全怎么保证？」**：字段级加密 + PII 脱敏 + 审计日志 + 主链路 dashscope 境内处理不涉及出境（出示供应商清单）。
- **「留存/付费指标如何？」**：试点数据口径如实提供；未达标项按优化中表述。

### 7.4 复盘节奏

- 试点第 2 周、第 4 周各做一次 NPS/留存复盘（漏斗数据 + 问卷回收），结论写入《试点验证报告》。
- 每季度把最新指标刷新进本话术，供企业 POC 与 12 月商业化发布共用。

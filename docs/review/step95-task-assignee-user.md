## 1. 数据模型

`tasks` 新增可空 `assignee_user_id`（FK users + 索引）：

- 新指派写 `assignee_user_id`，同时把显示名写进旧 `assignee` 文本快照；
- 历史任务只保留 `assignee` 文本，仍正常展示/导出，只是不能按用户通知；
- 不物理删除旧字段，避免历史通知、同步邮件、导出文案断裂。

迁移可逆，SQLite 下不建 FK，MySQL/PostgreSQL 建 FK。

## 2. 指派规则

| 操作 | 规则 |
| --- | --- |
| 创建时指派 | `assignee_user_id` 必须是同组织用户；否则 400 `TASK_ASSIGNEE_INVALID` |
| owner 改派/清空 | 支持；显示名快照同步更新/清空 |
| 负责人自己改派 | 403 `TASK_EDIT_FORBIDDEN` |
| 跨组织用户 | 拒绝，避免通知/可见性越界 |
| 历史文本负责人 | 仍可读；owner 改成真实用户后接续通知 |

## 3. 协作权限

| 角色 | 状态/进度 | 评论 | 标题/描述/截止/协作者 | 负责人 | 归档/恢复 |
| --- | --- | --- | --- | --- | --- |
| owner | ✅ | ✅ | ✅ | ✅ | ✅ |
| 负责人（非 owner） | ✅ | ✅ | ❌ 403 | ❌ 403 | ❌ 403（详情不显示按钮） |
| 同组织共享成员 | ❌ 403 | ❌ 403 | ❌ | ❌ | ❌ |

- API 403 使用稳定错误码：`TASK_EDIT_FORBIDDEN` / `TASK_COMMENT_FORBIDDEN`；
- 无可见性的任务仍返回 404，不泄露存在性；
- owner 权限不变，归档仍 owner-only。

## 4. 列表与提醒

- `scope=mine`（“我的”）= 我创建的 + 指派给我的；负责人可在自己的列表直接找到任务；
- `scope=shared`（“共享任务”）排除指派给我的任务；
- stats 的 `shared` 同步排除“我负责”的任务；
- 负责人标签显示「我负责」，表格新增「负责人」列；
- 到期/逾期提醒收件人改为 `assignee_user_id or task.user_id`，时区也按收件人通知偏好计算；
- 负责人未设置时回退 owner，历史行为不变。

## 5. 前端

- 统计/看板/表格沿用原有筛选，无新增入口。

## 8. 边界

1. **单负责人**：没有多负责人/负责人组；协作者仍是自由文本，不参与权限与通知。
2. **负责人不能改截止/标题/归档**：执行权与编辑权分离；如需要“负责人可改截止”需产品确认。
3. **负责人离职/调组织**：历史指派仍指向原 user_id；不会自动转交，也没有离职转派流程。
4. **只提醒负责人**：设置负责人后 owner 不再收到到期提醒，没有抄送 owner。
5. **历史文本负责人不能按用户通知**：只有 `assignee_user_id` 非空才走真实用户提醒。
6. **无批量改派**：一次一个任务；也没有按部门/案件批量指派。
7. **member 列表最多 100 人**：组织成员接口未分页，超大组织选择器可能不全。
8. **详情评论操作人显示 user_id**：评论列表仍是「用户 16」，没有显示姓名。
9. **`scope=mine` 语义变化**：从“我创建的”变为“我创建的 + 指派给我的”，旧用户可能感知列表变多。
10. **包体 +2.3 KB**：负责人下拉、表格列、权限提示与日志动作。

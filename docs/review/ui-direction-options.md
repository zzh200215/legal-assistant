# 律智检 · A/B/C 三套候选视觉方向

**基准参照**：`docs/review/ui-preview-direction-b.html`（现有实现）与 `frontend/src/styles/design-tokens.css`（现行令牌）。

## 方向 A ——「克制的工具感」（在现有令牌上做分级）

**设计意图一句话**：色板一字不改，只把层次交给 1px 边框、字号阶梯与间距——让界面显得安静、可信、像内部系统而不像演示页。

### 相对现有 `ui-preview-direction-b.html` 的改动
1. **去掉渐变与光晕**：品牌方块由 `linear-gradient(...)` + 彩色投影改成纯色 `--color-primary` 面；`--shadow-3: 0 20px 48px -20px rgba(79,70,229,.28)` 这种彩色光晕全部删除，卡片只用 `--shadow-xs`。
2. **圆角回收到令牌口径**：参照物用的是 16px/10px/7px 的自定圆角；A 改用 `--radius-lg:14px` / `--radius-sm:8px` / `--radius-xs:4px`，与 `design-tokens.css:72` 的注释「Border Radius：工具型产品口径，避免过圆的『气泡感』」一致。
3. **强调色收权**：主色只出现在选中态、链接、主按钮与引用角标（`.cite`）；导航徽标、统计数字、标签底色一律走中性灰。参照物里 `--teal` 同时用于徽标、统计数字、结论强调，颜色因此失去了「这里需要注意」的信号作用。
4. **引用核验从「一个徽标」改为「一条口径 + 逐条状态」**：参照物在右侧证据卡上只给了「已核验/待核验」两种色块；A 在中间引用列表逐条给出 `已核验 / 未核验`，并在上方固定一句「未核验引用不代表结论错误」。
5. **忠实度用中性色表达「未校验」**：`.faithful.is-unverified` 走 `--color-text-muted` 左边线 + `--color-surface-subtle` 底，不用绿色，也不伪装成警告红。

### 关键取舍
- **信息密度**：中。1440×900 内主栏可见「结论 + 事实要点 + 建议 + 引用核验口径」，引用列表需滚动约 1/3 屏；右栏可见处理过程全 4 步 + 答案 + 第 1 张证据卡（含条文原文）。
- **学习成本**：低。它和现有实现是同一套视觉语言，用户与开发都不用重新认界面。
- **实现成本**：**最低**。它基本等价于「把手写色值换成 CSS 变量 + 删掉渐变光晕」，现有页面几乎不需要改结构，改的多是 CSS 变量引用。

### 对 Element Plus 组件的贴合度
**最高（≈95% 直接可用）**。仓库已装 `element-plus ^2.8.0`（`frontend/package.json:25`），且 `frontend/src/styles/element-overrides.css:13-70` 已把 `--el-color-primary`、`--el-border-radius-base:8px`、`--el-border-color:#E3E5E9`、`--el-box-shadow-*` 全部对齐到 design-tokens。A 的取值与这批覆盖值同源，因此：
- 引用列表 → `el-table`（A 的行高与 `--el-table` 默认行高同档），或 `el-descriptions`；
- 时间线 → `el-timeline` + `el-timeline-item`（A 的圆点序号与它的默认形态接近）；
- 核验状态 → `el-tag`（`type=success/warning/info`，颜色已被覆盖文件对齐）；
- 主按钮 → `el-button type=primary`，无需额外覆盖。
**A 的优势就是：几乎不写新 CSS。**

### 风险
- 与现有实现差异最小，**可能显得「没改」**；如果这次改版的目标是「让人一眼看出升级过」，A 的说服力最弱。
- 强信息层级全靠字号与线，若后续有人往页面里加彩色徽标，会迅速退化成参照物那种「哪里都亮」的状态。

## 方向 B ——「高密度工具台」

**设计意图一句话**：把界面当办案工具台——一屏尽量多地看到事实、依据与核验口径，密度本身就是专业感。

### 与 A 的可陈述差异
1. **密度**：正文基准字号从 14px 降到 13px，行高 1.5，左导航行高 32px、顶栏 44px、卡片内边距用 8/10px 档（A 用 16/20px 档）。同样一屏，B 多显示约 30% 内容。
2. **层次表达**：**不靠卡片靠分隔线**。圆角压到 `--radius-xs:4px`，阴影只留 `--shadow-xs`；主栏由「面板 + 节标题 + 分隔线」构成，没有一堆悬浮的白卡。
3. **强调色用法**：主色只用于可点击/激活态；**青绿 `--color-accent` 只用于相似度数值**，形成「哪里是置信度指标」的固定信号。
4. **状态表达**：核验状态用 `--radius-xs` 的小方块标签，不用胶囊；数字口径前置（`3 已核验 / 1 未核验` 中数字放大到 14px，标签降到 11px）。
5. **引用列表变成真正的表格**：`# / 依据 / 引用内容 / 核验状态` 四列固定列宽，扫描时左侧对齐、右侧状态对齐——这是本方向最「工具台」的一处。
6. **右栏四层改为「等宽小标题 + 分隔线」区块**，处理过程用三列表格承接（步骤 / 详情 / 耗时右对齐等宽），证据卡不再有圆角气泡感。

### 关键取舍
- **信息密度**：**最高**。主栏一屏内「结论 + 3 段推理 + 事实要点 5 行 + 核验口径 + 引用列表 4 行」全部可见（实测 `contentScroll: 856` ≈ 一屏内基本读完）；右栏一屏内可见处理过程 4 步 + 答案 + 3 张证据卡 + 忠实度区块。
- **学习成本**：中。密度高，但所有数字用等宽字体右对齐、所有区块有固定标题位，熟练后扫描效率最高；对偶尔使用的用户略费眼。
- **实现成本**：中。表格化的引用列表与三列时间线需要自定义样式，`el-table` 的默认行高与内边距要覆盖（`--el-table-*` 已在 `element-overrides.css:186` 有覆盖先例，可直接扩展）。

### 对 Element Plus 组件的贴合度
**中高（≈80%）**，但**需要覆盖密度类变量**：`el-table` 走 `cell-padding`、`el-descriptions` 走 `label-width`、`el-timeline` 需要换成自定义表格（或保留 `el-timeline` 并接受它偏松的行距）。
- 引用列表 → `el-table`（**最贴合**，B 的表头/单元格结构与它一一对应）；
- 事实要点 → `el-descriptions :column="1"`；
- 步骤与耗时 → 建议自定义（`el-timeline` 没有「右侧耗时列」的位置）；
- 状态 → `el-tag` 但必须把 `--el-border-radius-base` 局部调回 4px。

### 风险
- **11px/13px 的信息栏对 40+ 律师偏小**，且这个产品要「显得可信」，过密会像监控大屏而不像法律工具。建议若选 B，把正文基准提到 14px、只压行高。
- 表格化引用列表在**窄主栏（<720px）会挤**，需要设计降级形态（比如收起「引用内容」列）。
- B 与 A 的差异集中在密度与分隔线，若在真机上只看一眼，**容易被误认为「同一套，只是缩放不同」**——选 B 前请务必看截图对比。

## 方向 C ——「留白阅读器」

**设计意图一句话**：把界面当一份可读的法律文书——一屏只讲清一件事，层次靠留白与细线，靠版面本身显得专业、可信。

### 与 A/B 的可陈述差异
1. **排版密度**：**最低**。主栏阅读宽度收窄到 620px 居中，正文字号升到 15px、行高 2.0；段落之间用 16–20px 留白而非线框分隔。同样一屏，主栏只到「事实要点」，引用列表要滚动。
2. **层次表达**：**几乎不用容器**。引用列表没有卡片、没有底色，只有序号（中文数字「一/二/三/四」）+ 一条 1px 上边线；右栏没有嵌套盒子，证据卡是「细线 + 宋体引文」。
3. **字体**：标题用宋体栈 `--font-serif`（本方向新增，非现有令牌），正文用现有 sans 栈。中文法律文书用宋体标题的「文书感」，是三个方向里视觉辨识度最高的一处。
4. **强调色用法**：**最保守**。主色只用于下划线链接与激活句；核验状态用**纯色文字**（`--color-success` / `--color-warning`），不铺底色；相似度用青绿文字。
5. **状态表达**：核验不是徽标而是**一行中性陈述**——「本答复共引用 4 条依据，其中 3 条已与法源库条目核验，1 条未核验」；忠实度的「未校验」用 `--color-text-secondary` 中性字色 + `--color-warning` 的 6px 短横线做项目符号，**任何地方都没有把「未校验」画成绿色**。

### 关键取舍
- **信息密度**：**最低**（实测主栏 `contentScroll: 1913`，约 2.3 屏）。适合「一屏讲清一个结论、其余交给滚动」，不适合需要横向比对多条依据的办案场景。
- **学习成本**：**最低**。没有徽标体系、没有密度门槛，任何第一次打开的人都知道该从哪读起——这是 A/B 都比不上的。
- **实现成本**：**中高**。难点不在 CSS 而在**元素层级**：现有实现大量依赖 `el-card` / `el-table` 这类天然带边框与底色的容器，C 要把它们拆掉重新用 `border-top` + 留白排版；宋体标题也需要在 `design-tokens.css` 里新增 `--font-serif`（现有只有 `--font-family` 与 `--font-mono`）。

### 对 Element Plus 组件的贴合度
**最低（≈60%）**，因为 C 的美感恰恰来自「少用组件」：
- 引用列表 → `el-descriptions` 或自定义 `<article>` 列表；**不建议** `el-table`（表格线会破坏留白）；
- 容器 → 去掉 `el-card`，用 `border-top` 分区；
- 结论/正文 → 纯 `<p>`，不需要组件；
- 状态 → `el-tag` 在这里偏重，改用纯色文字（`.vstate`）；
- 唯一高度贴合的是 `el-empty` / `el-skeleton` 这类无装饰组件。
> 也就是说，选 C 意味着**放弃一部分 Element Plus 的开箱即用**，换来最强的视觉辨识度。

### 风险
- **信息效率最低**：引用列表 4 条需要滚动约 1.3 屏，右侧 copilot 的「证据卡 ↔ 答案」在同一屏内无法互相参照——而 copilot 的逐句溯源恰恰依赖这种同屏对照。
- **宋体标题是审美赌注**：在 Windows 上会回落到 SimSun（点阵感明显），除非随包引入思源宋体，否则**同一份设计在不同机器上观感差异最大**。
- 620px 阅读栏在 1440px 屏上会产生大片空白，容易被读成「没做完」而非「刻意留白」。

## 我的推荐

**推荐方向 A，并按 B 的两处细节做增强。**

**一句话理由**：A 是唯一一个「零新增设计负债」的选项——它的每个色值、圆角、阴影都已经是仓库里 `design-tokens.css` 的现值，改造成本最低、回归风险最小，而这套界面的可信度本来就不该靠新配色去挣，而该靠「核验口径说得清楚」去挣。

具体增强两点（从 B 借，不改变 A 的性格）：
1. **引用列表借 B 的「状态列右对齐」**——现有列表里状态徽标跟在文字流末尾，多行时会跳位；固定一列右对齐后，扫一眼就知道哪条没核验。
2. **核验数字借 B 的「数字前置」**——把 `3 已核验 / 1 未核验` 里的数字加大到正文号，让「有 1 条没核验」这件事在页面里足够显眼；这是本产品最该被看见的一句话。

**什么情况下我会改推 B**：如果这次改版的目标是给招聘方展示「工程完成度与信息架构能力」，B 的一屏全貌在截图里最有说服力；但需要把正文基准提到 14px 再谈。

**什么情况下我会改推 C**：如果产品定位要往「给非律师看的法律意见书」走，或者未来要出 PDF/打印稿，C 的版面最接近交付物形态。

### 三套里**故意偏离**令牌的地方（需要一并确认）
1. **方向 C 的 `--font-serif`**：新增令牌，现有 `design-tokens.css` 没有。值取 `'Songti SC','Noto Serif SC','Source Han Serif SC',SimSun,Georgia,serif`。

## 需要用户拍板的点

1. **选哪一套**（我的推荐是 A + 借 B 的两处细节）。
2. **B 的字号是否偏小**：B 的正文基准 13px、元信息 11px，是为密度服务的；如果目标用户是 40+ 律师，可能需要整体上调 1px（会把「一屏读完」的卖点打掉一部分）。
3. **C 的宋体标题要不要保留**：如果不随包引入思源宋体，Windows 上会回落到 SimSun，观感比截图差。
4. **品牌色要不要换**：三套都沿用了现有靛蓝 `#4F46E5` + 青绿 `#0D9488`。如果希望「一眼看出改版了」，换品牌色是比换密度更有效的手段，但会影响 `element-overrides.css` 里一整组 `--el-color-primary-*` 派生值（`light-3/5/7/8/9`、`dark-2`），需要一起重算。
5. **「未核验」的呈现尺度**：三套都坚持「未核验 = 中性色，不用绿色、也不用警告红」。若产品希望它更醒目（比如用于催办），需要明确是否允许升格为 `--color-warning` 底。
6. **右栏 copilot 的收起态**：三套只演示了 380px → 52px 的壳，收起后那四层信息是否需要一个摘要入口（例如只留一个「3/4 已核验」圆点），本次没有设计。

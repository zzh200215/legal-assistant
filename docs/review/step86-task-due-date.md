## 1. 为什么补

页面副标题写着「跟进案件中的待办、负责人和截止日期」，看板/表格也在渲染逾期，但：

- 新建任务没有日期输入，`due_date` 只能由文档/聊天提取产生；
- 详情面板不显示截止日期，更不能改；
- 表格视图没有「截止」列，只有看板卡片能看到日期。

也就是说：截止日期是「只读的、偶尔由 AI 猜出来的」，用户无法维护。

## 2. 新建：日期落到当天 23:59:59

- 新建对话框加原生 `<input type="date">`（不引入 Element Plus date-picker，省包体）；
- `due_date` 提交为 `YYYY-MM-DDT23:59:59`：
  - 只到天的日期如果存 00:00，当天零点就会被判逾期；
  - 存 23:59:59 表示「当天内完成即可」；
- 不填日期时请求体完全不出现 `due_date`（保持旧契约）。

## 3. 详情：展示 + 修改 + 清除

- 描述区新增「截止日期」（过期标红，未设置显示「未设置」）；
- 协作更新区新增日期输入与「清除日期」；
- 保存时**只在用户改过日期时**提交 `due_date`：
  - 只改进度/协作者不会把原来的 `10:00` 改写成 `23:59:59`；
  - 清空后提交 `due_date: null` 真正删除；
- 共享只读任务仍禁用日期输入（沿用 `canEdit`）。

## 4. 表格：补「截止」列

表格视图在「案件」后新增「截止」列（100px），显示 `YYYY-MM-DD`，逾期标红；无日期显示 `—`。

## 7. 边界

1. **日期只到天、没有时间**：统一存当天 `23:59:59`，不支持精确到小时。
2. **时区沿用既有口径**：后端/数据库存 naive 时间，前端按本地时间解释；跨时区团队看到的「当天」以浏览器本地为准。
3. **旧数据不改写**：文档/聊天提取的历史任务仍可能是 `00:00:00`，当天就可能显示逾期；本步不批量改写。
4. **仅 owner 可改**：共享任务只读，日期输入禁用。
5. **没有到期提醒**：截止日期只参与展示与逾期标记，不发通知/不生成待办。
6. **表格列宽 100px**：`YYYY-MM-DD` 刚好；窄屏依赖表格横向滚动。
7. **原生日期控件**：视觉与 Element Plus 不完全一致，但没有引入 date-picker 依赖（省包体）。
8. **无后端/迁移改动**：创建/更新接口早支持该字段，本步只补 UI 与测试。
9. **包体 +2.8 KB**：主要来自详情/表格与日期输入，余量仍有 53.3 KB。

## 8. 后续建议

- 到期提醒：复用通知 Outbox，在 `due_date` 前 1 天/当天发站内提醒；
- 任务列表支持按截止日期排序（当前固定创建时间倒序）；
- 批量把历史 `00:00:00` 的截止日期规范到当天结束（需确认业务口径）。

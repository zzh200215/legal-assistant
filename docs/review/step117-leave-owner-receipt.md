# 第一百一十七步交付说明：请假回执（已生效 / 已恢复）

> 一句话：请假生效时给请假人一条「通知已转给 X」，结束或到期时给一条「通知已恢复给你」；按请假轮次去重，且不会被自己的代理转走。

## 1. 为什么

上一步让代理知道了「开始代收 / 已交还」，但请假人自己仍然看不到状态：

- 设完请假后，不确定是否真的生效、通知到底转给了谁；
- 回来上班时，不知道通知是否已经恢复给自己，容易重复追问代理或漏看。

两条回执把请假人的闭环补上：**设置 → 生效 → 恢复**，每步都有明确信号。

## 2. 触发时机

| 回执 | 收件人 | 时机 | 模板 |
| --- | --- | --- | --- |
| 已生效 | 请假人本人 | 设置时请假已生效 → 立即；未生效 → 开始日 09:10 扫描 | `leave_owner_started` |
| 已恢复 | 请假人本人 | 手动结束请假或到期清理时 | `leave_owner_resumed` |

- 两条都是站内 + 邮件，走请假人自己的渠道偏好与静默时段（非强提醒）；
- 回执 `on_behalf_of_user_id` 为空：这是本人的系统通知，不进入「代收」筛选；
- 正文写明请假区间与代理姓名，例如「你的请假已生效（2026-11-10 至 2026-11-20），期间所有事件类型的通知都会转给 Bob」。

## 3. 直达本人、按轮次去重

- **`allow_delegate=False`**：回执创建时不会走请假解析，否则刚设的代理会把它转走，请假人永远看不到「转给了谁」；
- **去重**：沿用上一步的 `leave_period` 轮次，幂等键为 `reference_type=notification_leave` + `reference_id=请假行` + `business_version=轮次` + 模板键；重复保存同一次请假不会重复发；
- **恢复回执的前置条件**：请假人确实收到过「已生效」回执才发。取消一段还没开始的请假，不会发「已恢复给你」；
- **换代理**：属于交接，只给请假人发新代理的「已生效」回执，不发「已恢复」；
- **代理无效**（停用/跨组织）：实际没有转发，因此也不发回执。

## 4. 边界

1. **老请假不补发**：本步上线前已生效、没有「已生效」回执的请假，结束时不发恢复回执。
2. **换代理不发恢复**：A → B 只发「已转给 B」，避免误导「通知回到了你」。
3. **借用 `deadline` 事件类型**：没有独立的「系统/设置」事件类型；请假人关掉关键日期渠道后，回执只剩站内。
4. **可被静默延后**：信息类通知，命中静默时邮件延后、站内即时。
5. **不新增扫描计数**：`leave_started` / `leave_ended` 仍只统计发给代理的通知，回执数量需从事件表自查。
6. **不要求确认**：回执只是通知，不改变请假设置，也没有「我已回来」按钮。
7. **无撤回**：请假结束后已发出的回执保留在通知中心。
8. **包体不变**：本步纯后端，总资产维持 1689.1 / 1700 KB（99% 预警档）。

## 5. 验证

- 已生效请假 → 请假人立即收到站内 + 邮件，标题/正文/引用正确；

- 重复保存 → 轮次不变、不重复回执；
- 结束请假 → 恢复回执一次，重复结束不重复；

- 取消未开始的请假 → 不发恢复回执；

- 回执不会被请假人自己的代理转走；
- 未设置代理 → 不发回执。

## 7. 后续建议

- 通知中心区分「请假代收 / 事件类型代收」，并在请假期间给本人一个全局提示（需先腾包体预算）；
- 请假结束回执里附「这期间有 N 条通知由代理处理」，让请假人知道是否需要回看；
- 请假开始前 1 天给代理一个预告，避免当天才被告知；
- 支持「提前回来」：结束请假时把时间段记入历史，便于复盘。

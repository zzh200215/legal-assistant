## 1. 为什么先做这部

交付说明 §5 的诚实边界写着「语料仍是节选：劳动合同法 98 条、劳动争议调解仲裁法 54 条全文；其余五部仍是节选（公司法 12 条、民法典合同编 17 条等）」。五部全文本合计约 950 条，一次性铺完的准确性风险很高，所以先挑一部做试点。

选《消费者权益保护法》的理由：

- 只有 **63 条**，2013 年修正文本稳定，适合作为「官方来源 → 逐条录入 → 校验 → 回填」的完整样板；
- 消费纠纷是产品里的常用场景（`consumer_dispute`），第 25/26/39/55 条是高频引用；
- 原节选只有 8 条，缺条文时条级核验只能显示「未收录」，效果最容易被看见。

## 2. 来源与解析口径

| 项 | 值 |
| --- | --- |
| 官方来源 | 中国人大网（全国人大常委会） |
| URL | `http://www.npc.gov.cn/npc/c2/c12435/c12488/201905/t20190521_184603.html` |
| 文本 | 1993-10-31 通过；2009-08-27 第一次修正；2013-10-25 第二次修正 |
| 施行 | 1994-01-01 施行；2013 年修正后自 2014-03-15 施行 |
| 条数 | 63 条，8 章 |
| 解析 | 读取页面 `<p>`，按「第 X 章」切章、「第 X 条」切条；保留条号、章节与分段，去掉标题行与编辑署名 |
| 规范化 | 全角空格与多余空白压成普通空格/换行；条号统一为 `第N条`（阿拉伯数字，与现有语料一致） |

`import_consumer_law_corpus.py` 在写盘前做四类校验：

1. 条数必须是 63；
2. `sequence` 必须是 1..63 连续；
3. 第 1/25/26/39/55/63 条必须各含一段关键文本（防止解析错位或截断）；
4. 任一条文正文不能为空。

`--check` 会重新抓取并与现有 JSON 比对，完全一致才返回 0；本次实测 `一致：63 条`。

## 5. 边界与剩余四部

**边界（如实）**：

1. **单一官方来源**：只从中国人大网抓取并逐条校验，没有和第二来源做全文 diff。条文正文与官方页面一致，但未做人工逐字校对。
2. **未保留条文标题**：只保留条号、章节、正文；现有节选里的 `title`（如「七天无理由退货」）没有回填，避免把编辑性标题混进法条。
3. **只同步演示法源**：`--sync` 按「去《》/括号后的标题」匹配；用户自己导入的同名法源也会被升级，非同名的不动。
4. **没有重跑咨询评审**：语料补全对咨询引用覆盖率的影响需要按 step16 的口径重跑，本文没有做。

# 第一百二十三步交付说明：通知中心「我代收了谁」汇总

> 一句话：代理人在通知中心只看到一条条零散通知，分不清在替谁处理；新增按原收件人分组的汇总面板（代收 N 条 · 未读 M · 最近时间），点一行即筛到该同事。总资产 1653.5 → **1657.7 KB**（+4.2 KB，98%）。

- 日期：2026-11-14
- 后端：`api/developer/notifications_onboarding.py`、`services/notification/notification_service.py`
- 前端：`views/Notifications.vue`、`api/notifications.js`、`tests/e2e/notifications-center.spec.js`
- 契约：OpenAPI **377 paths / 178 schemas / 28 error codes**；新增 1 个只读接口 + 1 个可选 query 参数（non-breaking），snapshot 已重基线
- 迁移：**无新增**（仍 124 个，head `20261114_0123`）
- 测试：后端新增 **8**；前端单测 124 不变；e2e **23 → 24**

## 1. 为什么

step120 给每条通知加了「请假代收 · X / 类型代收 · X」标签，单条归属清楚了；但代理人的真实界面是**一屏混杂好几个人的事**：

- 代收对象一多，标签只是重复出现，看不出「谁的事最多、谁还有未读」；
- 想只看某一位同事的通知，现有筛选只能按「请假代收 / 类型代收」，不能按人。

这一步把「代收了谁」做成聚合视图，点一行就等于按人筛选。

## 2. 做了什么

### 2.1 汇总接口 `GET /notifications/delegated-summary`

按 `on_behalf_of_user_id` 分组，返回：

```json
{"items": [{"user_id": 15, "name": "主办律师", "count": 7, "unread": 2,
            "last_at": "2026-11-14T09:00:00"}], "total": 1}
```

- 与通知列表同一口径（`channel=site`、`status != failed`），点开分组能筛到完全一致的一批；
- 排序：条数降序 → 最近时间降序；`limit` 默认 20、上限 50；
- 姓名解析与列表一样（`full_name` → `username` → `用户 id`）。

### 2.2 列表按人筛选

`GET /notifications/me` 新增可选 `delegated_from_user_id`（原收件人 id），与 `delegated`、`delegation_source` 可叠加；`0`/负数按 422 拒绝。

### 2.3 通知中心

| 位置 | 行为 |
| --- | --- |
| 页头下方 | 「我代收的对象 · 2 人 · 共 3 条」面板，可收起 |
| 每行 | 姓名 + `代收 2 条 · 未读 1` + 最近时间；点一行即按人筛选，当前行高亮 |
| 卡片顶部 | 筛选生效时显示「只看代 主办律师 的通知 ✕」，可一键清除 |
| 已读联动 | 标记已读时本地把该行未读数 −1，全部已读清零，不额外请求 |

窄屏下隐藏最近时间、行内两列，避免挤压。

## 5. 边界

1. **没有时间范围**：汇总统计当前用户全部代收历史（很早以前的也算），只有 `limit` 控制人数；按时间段查看要另加参数。
2. **按「原收件人」分组，不按请假轮次**：同一位同事请两轮假会合并成一行，看不出是第几次代收。
3. **未读数是本地同步的**：点「标记已读」只会改当前页面上的数字；在别的标签页/设备上读掉的通知，要刷新页面才会更新。
4. **点分组不写 URL**：筛选只存在于当前页面状态，刷新会回到默认列表；也不能把「只看某人」的链接发给别人。
5. **只统计站内、非失败通知**：与列表口径一致，邮件/微信投递不计入。
6. **包体已到 98%**：这一项 +4.2 KB，余量 42.3 KB；95% 预警档仍在，下一步动 UI 前必须先量产物。

## 6. 后续建议

- **汇总按时间窗过滤**：界面加「近 7 天 / 30 天」切换，接口加 `days` 参数，能回答「这周我替谁扛了多少」；
- **明细下钻**：给每行加「查看明细」，跳到已按人筛选的列表（本轮已具备筛选能力，只差入口串联）；
- 若要继续压包体，可评估 `@ctrl/tinycolor`（13 KB，仅 el-button 的 `color` 属性用、当前未使用）与 `el-input-number`（12 KB，仅两处数字输入）。

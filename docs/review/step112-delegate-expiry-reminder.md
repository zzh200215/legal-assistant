## 1. 行为

Celery beat 每天 **09:10**（Asia/Shanghai）执行 `check_delegate_expiring`：

1. 扫描 `delegate_user_id` 与 `delegate_end` 都非空的偏好；
2. 按偏好时区把当前时间换成当地日期；
3. `days_left = delegate_end - 当地今天`；
4. 只处理 `0 ≤ days_left ≤ 2`（今天、明天、后天）；
5. 给**原收件人**发站内 + 邮件：
   - 标题「通知代理将于 YYYY-MM-DD 到期」；
   - 正文「代理 X 将于今天/明天/N 天后到期（YYYY-MM-DD），之后通知恢复发送给你」；
6. `allow_delegate=False`：这条提醒不会再转给代理；
7. 默认尊重静默时段（命中时邮件延迟），与普通提醒一致；
8. 邮件按钮深链到 `/settings/notifications`（`reference_type=notification_preference`）。

## 2. 去重

- 去重键：用户 + 模板 + 标题；
- 标题包含结束日期，所以：
  - 同一用户、同一结束日期只提醒一次；
  - 同一用户有多个事件类型但结束日期相同，只发一条；
  - 延长结束日期后标题变化，会重新提醒一次；
- 幂等键用 `business_version = delegate_end.toordinal()`，不同结束日期不会互相覆盖。

## 3. 验证

新增 `tests/test_delegate_expiry_reminder.py`（11 条）：

- 结束日期在 2 天后 → 原收件人收到站内 + 邮件，代理无事件；
- 结束日期是今天 / 明天 → 正文分别含「今天」「明天」；
- 结束日期在 3 天后 / 已过期 → 不提醒；

- 静默时段命中 → 邮件延迟；

## 5. 边界

1. **只提醒一次**：同一结束日期不会重复催；延长后才会再提醒。
2. **提前量固定 2 天**：没有组织级/用户级配置。
3. **错过窗口不补发**：worker 停摆跨过结束日期后，`days_left < 0`，不会补发。
4. **只覆盖有结束日期的代理**：长期代理（`delegate_end=NULL`）不会收到到期提醒。
5. **提醒本身不代理**：即使原收件人配置了代理，这条也直接发给本人。
6. **不自动延长代理**：到期后只是恢复原收件人；设置清理由 [step113](step113-delegate-cleanup.md) 负责。
7. **无前端页面改动**：邮件按钮深链到通知偏好页。

## 6. 后续建议

- 代理到期前 7 天再提醒一次（多档提前量）；
- 到期后自动清空 `delegate_user_id`，避免设置残留；
- 全局请假模式：一次设置所有事件类型的代理与有效期；
- 摘要任务按 `summary_frequency` 聚合。

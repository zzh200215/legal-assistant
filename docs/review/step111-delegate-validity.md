## 1. 行为

- `legal_notification_preferences` 新增 `delegate_start` / `delegate_end`，类型为本地 `DATE`，可空；
- 代理是否生效：

| 配置 | 行为 |
| --- | --- |
| 两个都空 | 长期有效（与 step110 一致） |
| 只有开始日期 | 从该日期起生效 |
| 只有结束日期 | 到该日期止生效 |
| 开始 ≤ 今天 ≤ 结束 | 生效，代理代收 |
| 今天 < 开始 或 今天 > 结束 | 不生效，回退原收件人 |
| 开始 = 结束 = 今天 | 当天生效 |

- 「今天」按**原收件人偏好的时区**取当地日期，不是 UTC 日期；
- 结束日期含当天：请假到 11-20，11-20 当天仍由代理接收；
- 代理无效/停用/跨组织/指向自己仍然优先回退，有效期只是额外一层判断；
- 已经创建的历史事件不会因为代理过期而改投；只影响之后创建的通知；
- 强提醒（任务逾期升级、投递告警）仍然不代理。

## 2. 接口与前端

`PUT /api/developer/notification-preferences/me?event_type=...`

```json
{
  "delegate_user_id": 16,
  "delegate_start": "2026-11-10",
```

- 日期用 `YYYY-MM-DD`；`null` 清除；

- 前端同样校验开始不能晚于结束（`validatePreferenceForm`），并提示「留空表示长期有效，起止都含当天」。

## 5. 边界

1. **只影响之后创建的事件**：已投递/已排队事件不撤回、不改投。
2. **日期是当地日期**：按偏好时区解释，不按 UTC；跨时区用户看到的「今天」可能不同。
3. **过期不通知**：代理到期不会给原收件人或代理发提醒，需要自己看设置。
4. **不校验日期跨度**：没有最长请假天数限制。
5. **代理权限不变**：仍然只转发通知，不授予任务/案件访问权限。
6. **强提醒仍穿透**：升级类通知永远直达本人/管理员。
7. **摘要频率仍未生效**。

## 6. 后续建议

- 代理到期前提醒原收件人；
- 全局请假模式（一次设置所有事件类型）；
- 通知中心展示「代 X 接收」标签与代理筛选；
- 摘要任务按 `summary_frequency` 聚合。

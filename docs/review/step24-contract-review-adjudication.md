## 1. 为什么这次由 AI 判，而不是继续等人填

step21 的 14 条抽检表空了约一天，直接后果是「三层评审」实际只落地了两层——规则层和裁判层都能跑，但没有人告诉裁判「你判得对不对」。继续等的成本是无限期；换成**有口径、可复算的独立复核**，至少能拿到三样东西：

1. 一套写死的判定口径（§2），换人/换模型可以复算，不是拍脑袋；
2. 两个裁判的**系统性偏差**方向（§4），这比单个一致率更有用；
3. 人工到场时只需「确认 / 改判 14 条」，不用从零读合同。

代价必须写在最前面：**裁决者是 AI，不是人工**。裁决文件里 `adjudicator.kind = "ai"`，评分报告抬头写「AI 独立复核（非人工）」，抽检表里一旦填了 `- 人工结论：`，人工优先、裁决只补空缺。这条链路上任何地方都不会把 AI 的判断说成人类标注。

## 2. 口径（先定规则，再看结果）

**有据性（7 条）**——只判「事实性主张」：

- ✅ `correct`：合同写了什么、没写什么、写在哪，都能在原文核实；评价性/风险性表述（「可能不足以覆盖」「风险极高」）本身不扣分。
- ❌ `wrong`：出现原文没有的事实（条款、数字、主体），或把原文有的说成没有；**摘要对本系统自身输出的陈述**（如「识别 8 类条款」）与实际清单不一致，也算错误——这是用户唯一能直接验证的「事实」。
- `unknown`：原文不足以判断（本批 14 条都有完整正文，未使用）。

**质量（7 条）**——三条同时满足才算可接受（等价 `pass`）：

1. **覆盖**：该合同相关的核心条款类型都要点到（空壳合同按八大类衡量）；
2. **事实**：无编造、无误读；
3. **可执行**：建议里有具体要素（金额 / 期限 / 比例 / 主体 / 条款措辞），通篇「建议补充」不算。

**外部知识**：引用外部法律基准（LPR 四倍、司法实践比例）不按「编造」处理，但属于应有来源的表述，记备注；模型自行推导的数值（日 0.3% → 年化 109.5%）按可复核推导处理。

## 3. 结果

### 3.1 一致率（14 条抽检）

| 基准 | 总体 | 有据性（7） | 质量（7） |
| --- | --- | --- | --- |
| glm-5.2（同族） | **13/14 = 0.9286** | 6/7 = 0.8571 | **7/7 = 1.0000** |
| qwen-plus（跨模型） | **7/14 = 0.5000** | 5/7 = 0.7143 | **2/7 = 0.2857** |

- 14 条里裁决判 **11 条正确 / 3 条不可接受**（`contract-1-grounding`、`contract-1-quality`、`contract-4-quality`）。
- 95% Wilson 区间：glm [0.685, 0.987]、qwen [0.268, 0.732]——点估计 0.93 不等于「稳稳达标」，下界低于 0.8。
- 与 glm 的唯一分歧是 `contract-1-grounding`；与 qwen 分歧 7 条，集中在质量轴的 actionability（5 条）。

### 3.2 不接受的 3 条

| 条目 | 判 | 证据 |
| --- | --- | --- |
| `contract-1-grounding` | 错误 | 摘要称「共识别 8 类条款」，但风险清单只有 3 类（付款/违约/争议）；合同根本没有交付、知识产权、保密、终止条款——摘要把「没审到的」写成了「审过的」。 |
| `contract-1-quality` | 不可接受 | 覆盖 3/8 类、摘要与清单不自洽、建议是「考虑提高上限」「确认无异议」这类无参数表述。 |
| `contract-4-quality` | 不可接受 | 8 条建议全是「明确…要素」清单，无任何金额/期限/比例/措辞；同一段文字可以套到任何合同上。 |

### 3.3 两盏灯的偏差方向

- **qwen 严格是系统性的**：它要求条款草案级措辞，而产品输出是「要素清单 + 部分参数」，于是质量轴 2/7；这不是随机噪声，step21 已观察到同样的 pattern（qwen 质量 pass 0/7）。
- **glm 宽松也是系统性的**：只要「缺什么」说对了就给 pass（质量 7/7）。
- **同一模型换个问法就变了**：`contract-1` 的摘要虚报，glm 的**有据性**判忠实，glm 的**质量**判 review 时才写「摘要称识别 8 类条款与实际清单不符」。说明分歧主要来自问题框架，不是模型能力。

## 4. 读出来什么

1. **第三层的产出不是「再投一票」**，而是发现了规则层可以补的检查：**摘要自述覆盖 vs 实际清单一致性**。这条零模型可算（正则抽「识别 N 类 / N 项高风险」与 `clause_types`、`risk_levels` 对账），比再加一个裁判便宜，也更容易解释给用户。
2. **一致率对「可接受」的定义高度敏感**：质量轴若改成「必须有条款草案」，qwen 会从 0.29 跳到 0.9。所以单个一致率不能当结论，必须连同 rubric 一起报。
3. **同族裁判的一致性不能当独立证据**：本次裁决者在质量轴上与 glm 7/7 同向，恰说明「AI 判 AI」容易共享盲区；`contract-1` 这一条真正的价值，是它同时被两个裁判漏掉，却能被「对照自身输出」这种换问法抓到。

---

## 5. 诚实边界

1. **裁决者是 AI**（deepseek-v4.1-flash），不是人工标注；与 glm 同向不代表独立，质量轴 7/7 就是证据。
2. **样本小且有重复**：7 条记录 / 14 条目里，`contract-4/5/6` 是同一份 18 字合同的重复输出，独立样本实际只有 5 份合同。
3. **历史记录不是当前 prompt 复跑**（step21 的边界不变），数字只作方向性证据。
4. **只量了「裁判 vs 裁决」**，没有量「产品 vs 真实律师」；后者需要真实法务参与，本轮没做。
5. **`contract-3` 的 LPR 表述判 correct 是口径选择**：我按「外部法律基准不算编造」处理；若产品要求「引用必须带法源」，这条应改判 wrong，一致率会变成 glm 12/14、qwen 8/14。
6. **一致率的置信区间很宽**（glm 下界 0.685），不能声称「合同审查达到 0.93」。

## 6. 复现

```powershell

.\.venv\Scripts\python.exe -B scripts\run_contract_review_review.py `

```

## 7. 下一步（按杠杆排序）

1. **规则层补自洽性检查**：摘要里「识别 N 类 / N 项高风险」要与实际 `clause_types` / `risk_levels` 对账，不一致直接降级或标注——本次唯一硬缺陷就是它，且零模型可做。
2. **人工复核 3 条不可接受 + `contract-3` 的 LPR 口径**：法务 10 分钟就能把 AI 裁决变成人工裁决，届时把 `adjudicator.kind` 改成 `human`、重跑第 6 节即可，不需要改代码。
3. **用当前 prompt 复跑 5–8 条新合同**，与这 7 条历史记录分开报，避免把旧 prompt 的结论当现状。
4. **质量轴拆成三个二值判断**（覆盖 / 事实 / 可执行）而不是一个 `pass`，减少「可接受」定义摆动带来的假分歧。

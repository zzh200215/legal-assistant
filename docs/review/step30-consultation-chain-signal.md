# 第三十步交付说明：审核队列里的咨询证据链信号

> 一句话：审核律师在队列里直接看到「这条咨询没有法源依据」——无依据标红、依据弱标橙，页头给出无依据咨询数，详情里附引用/句级溯源/忠实度一行摘要。只是信号，不阻断审核。

- 日期：2026-10-22
- 前端：`LegalReviewTab.vue`（队列标签、页头计数、详情标签与摘要行）
- 后端：无接口变更——队列行本来就带 `evidence_summary`（step29 读时派生），这里只是把它用起来
- 测试：`tests/test_consultation_evidence.py` +1 例、`frontend/tests/e2e/u3-workflow.spec.js`

---

## 1. 信号规则

| 等级 | 队列标签 | 说明 |
| --- | --- | --- |
| `none` | 无依据（红） | 一条法源引用都没有 |
| `weak` | 依据弱（橙） | 有引用但句级覆盖 <50%，或忠实度校验未通过 |
| `partial` / `strong` | 不显示 | 避免队列噪音 |

只对 `target_type === 'consultation'` 生效：合同审查走证据链缺口门禁（step25），文书没有证据链摘要。

## 2. 展示位置

1. **队列行**：类型标签旁直接标「无依据 / 依据弱」；
2. **页头计数**：`无依据咨询 N`（为 0 时不占位）；
3. **详情头**：同样的标签；
4. **详情「证据 / 法源」区块**：一行摘要 `无引用 · 未生成句级溯源 · 忠实度未校验` 或 `引用 1 条 · 句级溯源 3/4 句 · 忠实度通过`。

## 3. 队列筛选（与服务端同口径）

```
GET /api/legal/review-queue?evidence_level=none|weak|partial|strong
```

- 服务端在返回前过滤：**只返回该依据等级的咨询**（合同/文书没有 `evidence_summary`，不参与）；非法值 422；
- 前端队列筛选新增「全部依据 / 无依据 / 依据弱 / 部分 / 强」，切换即重新请求（`queueFilters` 深度监听）；
- 页头「无依据咨询 N」变成可点按钮：点一下切到 `evidence_level=none`，再点恢复；筛选激活时按钮高亮；
- 筛选无结果时空态显示「没有符合依据筛选的咨询。」，与「当前没有待处理审核。」区分。

## 4. 验证

| 项 | 结果 |
| --- | --- |
| 后端 | `test_review_queue_carries_chain_signal`：待审无引用咨询进队列后，行上 `evidence_summary.level === "none"`、`references === 0` |
| 后端筛选 | `?evidence_level=none` 只回无依据咨询（合同不返回）、`?evidence_level=partial` 只回有引用咨询、无筛选回 3 条、非法值 422 |
| e2e（u3） | 队列新增一条无依据咨询 → `queue-chain` 标签文本为「无依据」、页头出现「无依据咨询」计数；选中「无依据」→ 队列 4 条变 1 条且只剩该咨询、页头按钮高亮，复位后恢复 4 条 |
| 前端 | lint 0 error、build 通过 |

## 5. 边界

1. **只是信号，不阻断**：无依据咨询仍可通过审核（合同侧的高风险缺口才会 409）。
2. **阈值固定**：`weak` 沿用 step29 的等级口径（覆盖率 <50% 或忠实度 fail），没有让组织自定义。
3. **队列筛选只作用于咨询**：选「无依据」时合同/文书不返回（它们没有证据链摘要）；咨询 tab 的筛选仍独立存在（step29 §2.2）。
4. **合同/文书不参与**：同一队列里合同审查有自己的缺口门禁，两者不混用一套标签。
5. 老记录没有 `evidence_summary` 时按 `none` 处理——它们确实没有可展示的引用链。

# 第一百二十七步交付说明：通知中心筛选写进 URL

> 一句话：状态、类型、来源、时间窗、按人筛选与案件号全部同步到 URL——刷新、分享、后退都能回到同一屏；非法参数自动回落到默认。总资产 1638.5 → **1639.7 KB**（+1.2 KB，96%）。

- 日期：2026-11-16
- 前端：`views/Notifications.vue`、`tests/e2e/notifications-center.spec.js`
- 后端：无改动
- 契约：OpenAPI **377 paths / 178 schemas / 28 error codes**（无接口变化）
- 迁移：**无新增**（仍 124 个，head `20261114_0123`）
- 测试：前端单测 129 不变；e2e **24 → 25**；后端 2709 不变

---

## 1. 为什么

通知中心有六个筛选（状态 / 类型 / 来源 / 时间窗 / 按人 / 案件号），但都只存在组件状态里：

- 点完「明细」刷新一下就全丢了；
- 同事问「他那些代收通知在哪看」，只能口述路径，没法直接发链接；
- 浏览器后退直接离开页面，而不是撤销上一次筛选。

## 2. 做了什么

### 2.1 参数与筛选一一对应

| URL 参数 | 对应筛选 | 取值 |
| --- | --- | --- |
| `status` | 状态 | `all`（默认，不写）/ `unread` / `read` |
| `event_type` | 类型 | 五种事件类型 |
| `delegated` | 来源 | `own` / `delegated` / `leave` / `event` |
| `days` | 时间 | `7` / `30` |
| `delegated_from` | 按人 | 用户 id（数字） |
| `case_id` | 案件号 | 数字 |

### 2.2 三个方向的同步

| 方向 | 行为 |
| --- | --- |
| 打开页面 | `applyQuery(route.query)` 先还原筛选，再按参数请求列表与汇总 |
| 改筛选 | `resetAndLoad` 里先 `syncQuery()`：有变化才 `router.push`（相同参数不产生导航） |
| 后退 / 前进 / 手改 URL | `watch(route.query)` 对比差异，变了才重设筛选并重拉；自己 push 引发的回调因为值已相同，不会二次请求 |

### 2.3 容错

`normalizeQuery` 只接受页面认识的值：未知 `status`、非 7/30 的 `days`、未知 `delegated`、未知 `event_type`、非数字的 id 一律回落到默认，页面不会因为一条乱拼的链接进入坏状态。

## 4. 验证

- 新增 e2e（「筛选写进 URL，刷新与后退能还原」）：
  - 带 `?status=unread&days=7&delegated=leave&event_type=deadline` 打开 → 四个控件回显、请求参数一致；
  - 改状态为「已读」→ URL 出现 `status=read` 且其它参数保留；
  - `page.goBack()` → 状态回到「未读」并重新请求；
  - `page.reload()` → 仍按 URL 参数加载；
  - 故意传 `status=deleted&days=999&delegated=someone` → 三个控件回落到默认值；
- 既有 3 条通知中心 e2e 与任务中心 20 条 e2e 全部通过；
- 前端 lint 0 error（12 条既有 warning）；
- 包体：1638.5 → **1639.7 KB（96%）**，四项预算仍全绿；
- 全量门禁：**11/11，exit 0，50.4 分钟**（本机负载高：后端 38 分 54 秒、e2e 2.9 分钟）；后端 **2709 passed / 4 skipped**，前端单测 129、e2e 25、OpenAPI 377、迁移 124 全绿。

## 5. 边界

1. **用 push 而不是 replace**：后退可以撤销最近一次筛选，但连续改五个筛选就会留下五条历史记录；如果嫌吵，改成 replace 即可（会失去「后退撤销筛选」）。
2. **页码不进 URL**：深链打开永远从第 1 页开始；翻页后刷新会回到第 1 页。
3. **非法参数静默回落**：不提示「参数不合法」，直接按默认筛选（对分享链接更友好，但用户不会知道参数被忽略）。
4. **「我代收了谁」的展开/收起状态不进 URL**：它是视图偏好，刷新后回到展开。
5. **姓名依赖汇总接口**：深链里 `delegated_from=16` 打开时，上下文条先显示「用户 16」，等汇总返回后才换成姓名。
6. **包体仍是 96%**：这一项 +1.2 KB，余量 60.3 KB。

## 6. 后续建议

- **让「我代收了谁」的分组也支持深链**：现在点分组会把 `delegated_from` 写进 URL，可以再加一条「复制该人明细链接」的入口；
- **页码进 URL**（`page=2`）：列表翻页也能分享，配合 `replace` 更安静；
- 若继续做通知中心：给汇总行加「按事件类型分布」的小色条，回答「这个人主要是什么类型的通知」，预计 +2~3 KB。

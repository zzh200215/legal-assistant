# 第八十七步交付说明：任务搜索与截止排序

> 一句话：任务中心支持按标题/描述搜索、按截止日期排序，`q`/`sort` 全部下推服务端并写回 URL；空结果、深链、清除筛选与浏览器后退都能正确还原。

- 日期：2026-10-31
- 后端：`api/tasks/task_api.py`、`services/jobs/task_service.py`
- 前端：`views/Tasks.vue`
- 契约：`docs/openapi-snapshot.json` 重新导出（`q` + `sort` 两个查询参数，路径仍 370）
- 测试：共享/任务单测 **22 passed**；任务 e2e **7 passed**；前端单测 **100 passed**
- 无迁移；包体 **1648.6 / 1700 KB**（余 51.4 KB）

---

## 1. 为什么补

任务中心此前只能按 状态/范围/来源/案件 筛选，列表固定「创建时间倒序」：

- 任务一多（>12 条/页）只能翻页找标题；
- 逾期任务不会优先，截止日期只在卡片上展示；
- 筛选状态不能通过链接分享，刷新后搜索/排序无法保留。

## 2. 后端

`GET /tasks/` 新增两个查询参数：

| 参数 | 说明 |
| --- | --- |
| `q` | 关键词，匹配 `title` 或 `description`；`max_length=100`，前后空白裁剪 |
| `sort` | `created_desc`（默认）/ `due_asc` / `due_desc`，非法值 422 |

实现要点：

- `Task.title.icontains(q, autoescape=True)` / `Task.description.icontains(...)`：`%`、`_` 按字面量处理，不被当通配符；
- 排序白名单集中为 `TASK_LIST_SORTS`，`due_asc` / `due_desc` 都把 `due_date IS NULL` 放最后，避免不同数据库 NULL 顺序不一致；
- `count` 与分页共用同一组过滤条件，total 与列表一致；
- 默认排序保持 `created_at desc, id desc`，不改现有行为。

## 3. 前端

任务清单卡片内新增工具栏：

- 搜索框：350ms 防抖；Enter 立即提交；清空即恢复；只在关键词变化时请求；
- 排序下拉：最近创建 / 截止最近 / 截止最远；
- `q`、`sort` 写入 URL（默认排序不写 `sort`），刷新/分享/后退可还原；
- 搜索/排序变化时回到第 1 页；空结果显示「没有匹配「关键词」的任务」；
- 其余筛选（范围/来源/案件）与搜索、排序组合生效。

## 4. 验证

后端（`test_task_list_search_and_sort`）：

- `q=合同` → 标题命中 + 描述命中两条，未命中的不返回；
- `q="  合同  "` 与 `q=合同` 一致；`q=付款条款` 只命中描述；
- `q=%` → 0 条（通配符被转义）；
- `sort=due_asc` → 日期早的在前、无日期最后；`due_desc` 反之；
- 默认排序仍是创建时间倒序；
- `sort=bad` / `q` 超过 100 字 → 422。

任务 e2e（新增用例）：

- 输入「合同」→ 350ms 后请求带 `q=合同`，URL 带 `q`，列表只剩命中项；
- 切「截止最近」→ 请求带 `sort=due_asc`，URL 写回；
- 清空搜索 → `q` 从 URL/请求移除，列表恢复；
- 深链 `/tasks?q=归档&sort=due_desc` → 输入框与排序下拉正确初始化，列表只显示命中项。

## 6. 边界

1. **`%关键词%` 是全表/索引外扫描**：没有全文索引；数据量大时需要 FULLTEXT（MySQL ngram）或独立搜索表。
2. **只搜标题和描述**：不搜负责人、协作者、案件名、评论；多关键词没有 AND/OR 语法，按整段子串匹配。
3. **大小写/分词**：SQLite 对 ASCII 大小写不敏感、中文按原样子串；MySQL 依赖排序规则；不做分词。
4. **排序只有三种**：没有「逾期优先」「按优先级」自定义排序；`due_asc` 中逾期任务自然排在最前。
5. **统计卡仍是当前页**：任务总数/进行中/逾期/共享来自当前页数据，不是全量聚合。
6. **搜索/排序共享分页**：翻页保留 `q`/`sort`；切到看板/表格也保留。
7. **URL 写回是 replace**：不会为每次输入新增历史记录；后退会回到上一次实际提交的关键词。
8. **包体 +1.9 KB**：输入框与排序控件复用已有 Element Plus 依赖，余量仍有 51.4 KB。

## 7. 后续建议

- 逾期优先/截止升序的组合排序（`overdue_first`）；
- 保存常用筛选（范围 + 关键词 + 排序）；
- 数据量上来后把 `q` 换成全文索引或独立搜索服务；
- 任务统计改为全量聚合接口，避免分页口径。

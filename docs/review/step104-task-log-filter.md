> 一句话：任务日志支持按动作筛选、`limit/offset` 分页与 `asc/desc` 排序；详情默认加载最新 20 条，可「加载更多」，不再一次性拉全量。

## 1. 接口

`GET /tasks/{task_id}/logs`

| 参数 | 说明 |
| --- | --- |
| `action` | 按动作精确筛选（created/status_changed/comment_added…） |
| `limit` | 1–100，返回条数 |
| `offset` | 偏移，默认 0 |
| `order` | `asc` / `desc`，默认 `desc`（最新在前，保持原行为） |

- 响应仍是日志数组，未传 `limit` 时兼容旧的全量调用；
- `action` 不校验枚举，未知动作返回空列表；
- `limit > 100` 由 FastAPI 返回 422。

## 2. 前端

- 详情「操作日志」上方新增动作下拉（全部/创建/状态/进度/评论/编辑/删除/负责人/优先级/归档/恢复）；
- 默认请求 `limit=20&order=desc`，最新 20 条；
- 返回满 20 条显示「加载更多」，按 `offset` 追加；
- 切换动作重置 offset 并重新加载；
- 筛选后无结果显示「当前筛选下暂无日志」；
- 评论新增/编辑/删除后日志仍自动刷新。

## 5. 边界

1. **无总数/页码**：只按返回条数判断是否还有更多；数据被删时可能少一页。
2. **offset 分页**：新增日志会推移分页边界，加载更多可能重复/漏一条；不是稳定游标。
3. **动作筛选是精确值**：不做分组（如「所有评论」需选三个动作之一），未知动作返回空。
4. **前端固定 20 条**：没有用户可选 page size。
5. **按时间排序**：同一秒内按 id 兜底；不提供按操作人筛选。
6. **日志仍不可删除/导出**。
7. **包体 +1.6 KB**：动作下拉、加载更多与空状态。

## 6. 后续建议

- 游标分页（before_id）替代 offset；
- 操作人筛选与日志导出；
- 分组动作（评论类/状态类）；
- 用户可选 page size。

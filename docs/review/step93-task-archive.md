## 1. 数据模型

`tasks` 新增可空 `archived_at`（带索引）：

- `NULL` = 未归档；
- 非空 = 归档时间；
- 不物理删除，评论/日志/来源/案件关联全部保留。

迁移可逆，重复执行有列存在性保护。

## 2. 后端行为

| 接口 | 行为 |
| --- | --- |
| `POST /tasks/{id}/archive` | 仅 owner；幂等；写 `archived` 日志 |
| `POST /tasks/{id}/unarchive` | 仅 owner；幂等；写 `unarchived` 日志 |
| `GET /tasks/?archived=true` | 只看已归档；默认只看未归档 |
| `GET /tasks/{id}` | 归档任务仍可读 |
| 列表 stats | 跟随 `archived` 过滤；默认统计不含归档 |
| 到期/逾期提醒 | 跳过 `archived_at` 非空的任务 |

- 非 owner 归档/恢复返回 404（不暴露任务存在）；
- 列表的 `status`/`overdue`/`scope`/`q` 与 `archived` 可组合；
- 归档不改变任务状态、进度、截止日期。

## 3. 前端

- 清单工具栏右侧新增「查看已归档 / 返回未归档」切换，写 URL `archived=1`；
- 统计卡总数在归档视图显示「归档任务」；其他卡筛选在归档视图内继续生效；
- 详情页归档任务显示「已归档」标签，footer 显示「恢复」；未归档 owner 显示「归档」；
- 归档/恢复成功后关闭详情并刷新列表；归档视图下恢复会从列表消失；
- 空状态提示「暂无已归档任务」。

## 6. 边界

1. **归档是视图过滤，不是权限**：默认列表隐藏，但同组织成员在「已归档」视图仍可能看到共享任务；owner-only 只限制归档/恢复动作。
2. **仅 owner 可归档/恢复**：admin/部门成员不能代操作。
3. **归档不冻结编辑**：任务仍可通过详情更新字段/评论（API 未加锁），恢复后继续使用。
4. **子任务不级联归档**：只归档当前任务；子任务列表仍按父任务 ID 查询。
5. **无批量归档/自动归档**：一次一个任务，也没有「完成后 N 天自动归档」。
6. **无物理删除/保留期**：归档数据永久保留，后续需要清理策略。
7. **日志动作仍是英文**：`archived`/`unarchived` 与既有 `created/status_changed` 一致，未做中文化。
8. **归档视图仍受可见性约束**：不能借 `archived=true` 越权查看其他组织任务。
9. **包体 +2.0 KB**：切换按钮、归档标签与详情按钮。

## 7. 后续建议

- 批量归档/恢复；
- 「完成后 N 天自动归档」定时任务；
- 归档保留期与物理清理；
- 操作日志动作中文化；
- 归档任务只读（禁止编辑/评论）或明确允许。

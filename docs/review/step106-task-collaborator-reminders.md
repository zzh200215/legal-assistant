## 1. 收件人口径

| 任务情况 | 收件人 |
| --- | --- |
| 有负责人 | 负责人 + 全部协作者 |
| 没有负责人 | owner（创建人）兜底 + 全部协作者 |
| 同一人既是负责人/owner 又是协作者 | 只发一次，按负责人/owner 模板 |
| 已完成 / 已取消 / 已归档 / 无截止日期 | 不提醒（沿用原口径） |

- 协作者来自 `task_collaborators`（step98 的真实用户关联），不是旧的文本快照；
- owner 在有负责人时不再额外收提醒，保持 step95 的口径不变；
- 收件人顺序固定：负责人/owner 在前，协作者按加入顺序，便于测试与排查。

## 2. 阶段与去重

四个阶段不变：明天到期、今天到期、逾期 1 天、逾期 3 天。

- 去重键从「任务 + 阶段」细化为「任务 + 收件人 + 模板键」，所以负责人和协作者各收各的，互不吞提醒；
- 同一个人同一阶段重复扫描只发一次；
- 阶段变化（明天 → 今天）会再发一次，负责人和协作者都一样；
- 把协作者移除后再加回来，不会补发已经发过的阶段；
- 预取已有提醒事件，避免按收件人逐个查库。

## 3. 模板与渠道

新增 4 个内置邮件模板：

| 模板键 | 文案重点 |
| --- | --- |
| `task_collaborator_due_tomorrow` | 你参与的任务将于明天到期 |
| `task_collaborator_due_today` | 你参与的任务今天到期 |
| `task_collaborator_overdue_1d` | 你参与的任务已逾期 1 天 |
| `task_collaborator_overdue_3d` | 你参与的任务已逾期 3 天 |

- 站内标题带「协作者提醒 · 」前缀，例如「协作者提醒 · 任务今天到期：起草合同初稿」；
- 邮件正文用「你参与的任务」，页脚提示「如需调整分工，请联系任务负责人」；
- 渠道沿用 `deadline` 事件偏好：站内始终创建；邮件仅在组织配置了外发策略且用户偏好未关闭 email 时进入 Outbox；
- 内置模板从 13 个增至 **17 个**，管理页的「内置模板」列表自动出现新键。

## 4. 深链

- 站内通知：通知中心页现在和铃铛一致，点击任务提醒直达 `/tasks?taskId=N`（有案件时附带 `case_id`）；
- 邮件按钮：`action_url()` 新增 `reference_id` 参数，任务类提醒生成 `/tasks?taskId=N`，不再统一落到通知中心；
- 其他类型（咨询/合同审查/文书/投递看板）路径不变。

## 7. 边界

1. **协作者没有独立开关**：沿用 `deadline` 事件偏好，不想收只能整体关闭关键日期提醒。
2. **站内通知不受静默时段影响**：静默时段只影响邮件等外部渠道，这是既有行为。
3. **不做升级**：协作者逾期不处理，不会自动通知 owner 或升级提醒。
4. **不做汇总**：仍按任务逐条提醒，没有每日/每周摘要。
5. **协作者限同组织**：step98 的成员解析已限制同组织，跨组织用户不会成为协作者，也就不会收到提醒。
6. **无组织任务跳过**：沿用原逻辑，计入 `skipped_no_org`。
7. **包体只 +0.1 KB**：通知中心增加了任务路由分支，没有新增页面或组件。

## 8. 后续建议

- 协作者专属免打扰（按角色而不是只按事件类型）；
- 逾期升级：协作者逾期 N 天仍未处理时提醒 owner；
- 每日/每周任务摘要，替代逐条提醒；
- 通知偏好页展示「协作者提醒」的实际收件范围。

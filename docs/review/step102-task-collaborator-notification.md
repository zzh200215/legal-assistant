> 一句话：任务新建或改派协作者时，给**新增的**协作者发一条站内通知（「你被加入任务：X」），点击直达任务详情；owner/负责人本人不重复通知，重复保存不重复发。

## 1. 触发规则

| 场景 | 是否通知 |
| --- | --- |
| 新建任务时选择协作者 | 给每位新增协作者发站内通知 |
| owner 追加协作者 | 只给新增的人发 |
| 重复保存相同协作者列表 | 不发（按新增集合差集计算） |
| 移除协作者 | 不发 |
| 新增的人是 owner / 负责人 | 跳过 |
| 任务无组织 | 跳过（通知需要 organization_id） |

## 2. 通知内容

- `event_type=workflow`，渠道 **site**（站内即时 delivered；不发邮件）；
- 标题：`你被加入任务：{任务标题}`；
- 正文：`任务 #{id} · 由 {操作人} 邀请协作`；
- `reference_type=task`、`reference_id=任务 id`，通知中心/Bell 点击直达任务详情；
- `business_version=task.version`：移除后再加回会作为新版本重新通知，但同一版本内不会重复。

## 5. 边界

1. **只有站内信**：不发邮件/微信/飞书，也不受通知偏好里的渠道影响（站内始终创建）。
2. **只在加入时通知**：到期/逾期仍只提醒负责人；协作者不会收到任务到期提醒。
3. **重复保存不发**：按「新增 user_id 差集」判断；移除后重新加入会按新版本再发一次。
4. **无单独模板**：标题/正文硬编码在服务层，不走 `BUILTIN_EMAIL_TEMPLATES` 可编辑模板。
5. **通知事件类型复用 workflow**：通知中心按 workflow 归类，不是独立 task 类型。
6. **无批量加协作者**：批量改派/批量操作不涉及协作者通知。
7. **用户删除/离职**：历史通知保留，任务关联不自动清理。
8. **包体 0 KB**：纯后端。

## 1. 接口

`POST /tasks/bulk-reassign`

```json
{ "task_ids": [1, 2, 3], "assignee_user_id": 16 }
```

- `task_ids`：1–100 条，自动去重；
- `assignee_user_id`：同组织用户；传 `null` 表示清空负责人；
- 返回 `{updated, skipped, assignee_user_id, assignee}`。

规则：

- 只处理当前用户为 owner 的任务；非 owner / 不存在 → `skipped`；
- 选中的任务组织与目标负责人组织不一致 → `skipped`（避免跨组织指派）；
- 目标负责人不存在/跨组织 → 整个请求 400 `TASK_ASSIGNEE_INVALID`，不做部分成功；
- 改派写 `assignee_changed` 日志；同一负责人重复提交幂等（不重复写日志）。

## 2. 前端

- 表格视图新增多选列，底部出现批量操作条：「已选 N 项 + 新负责人下拉 + 批量改派 + 取消」；
- 负责人下拉复用组织成员接口；成员为空时按钮禁用；
- 留空提交 = 清空负责人；
- 成功后提示「已改派 X 项，跳过 Y 项」，清空选择并刷新列表；
- 仅表格视图支持；看板不显示批量条。

## 5. 边界

1. **仅 owner 可改派**：共享成员选中后被 skipped，不会报错；没有管理员代改派。
2. **一次最多 100 条**：超出由 API 422 拒绝。
3. **仅表格视图 + 当前页**：没有跨页全选；看板不支持批量。
4. **无二次确认**：点「批量改派」立即执行；清空负责人也立即执行。
5. **部分成功不返回明细**：只返回 updated/skipped 数量，没有逐条原因。
6. **跨组织目标整批拒绝**：不会部分任务成功、部分失败。
7. **归档任务也可改派**：批量接口不按 `archived_at` 过滤；默认列表看不到归档任务。
8. **成员接口最多 100 人**：超大组织的负责人下拉可能不全。
9. **无异步任务**：100 条同步处理；更大批量需要后台任务。
10. **包体 +2.0 KB**：多选列、批量操作条与负责人下拉。

## 6. 后续建议

- 大批量改后台任务 + 进度。

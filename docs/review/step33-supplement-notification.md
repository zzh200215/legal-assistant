# 第三十三步交付说明：补充完成后通知审核律师「引用 +N，覆盖 X%」

> 一句话：提交人按「去补充」追问成功后，之前退回的审核律师会收到一条通知——标题直接写「咨询已补充依据：引用 +1，覆盖 75%」，点开就是带「补充前后对比」的新结果卡。

- 日期：2026-10-23
- 后端：`app/services/legal/legal_workspace_service.py`（追问时算句级映射 + 退回后补发通知）
- 前端：无改动（通知列表/铃铛已有；点击按 `reference_type=consultation` 跳到新咨询结果卡）
- 测试：`tests/test_legal_review_assignment.py`（+2 例）

---

## 1. 触发条件

| 条件 | 说明 |
| --- | --- |
| 动作是「追问」 | `create_consultation_followup`（含从通知「去补充」进入的追问） |
| 原咨询状态是 `returned_for_facts` | 即「退回后补充」；普通追问不通知 |
| 提交人属于某组织 | 无组织无人可通知 |

**收件人**：同组织 `legal_role in (admin, reviewer)`，排除提交人本人。

## 2. 通知内容

- 标题：`咨询已补充依据：引用 +{added}，覆盖 {rate}%`（有移除时追加 `，移除 N`；无溯源时覆盖显示 `—`）
- 正文：`「问题前 40 字」补充后：引用 0 → 1（+1/-0） · 句级覆盖 —% → 75% · 等级 none → partial。请重新审核。`
- `template_key=consultation_supplemented`，`reference_id` 指向**新**咨询（点开即带对比块）
- 事件类型 `approval`

## 3. 顺带修的两处

1. **追问也计算句级映射**：此前只有首次咨询算 `attribution_json`，追问记录没有，导致「补充前后对比」的覆盖率永远是 `—`。现在追问生成后同样调用 `attribute_sentences_to_references`（失败只记日志）。
2. **追问里的用户对象在 `expunge_all` 后可能失效**：把 `org_id / actor_id` 在 expunge 前捕获，通知与活动记录都用捕获值，避免 detached instance 报错。

## 4. 验证

| 项 | 结果 |
| --- | --- |
| 后端 | 退回后追问 → 审核律师收到 1 条通知，标题「咨询已补充依据：引用 +1，覆盖 75%」、`template_key=consultation_supplemented`、`reference_id` 指向新咨询、正文含「引用 0 → 1」 |
| 后端 | 未退回的普通追问 → 不产生通知 |
| 门禁 | 见提交说明 |

## 5. 边界

1. **只对「退回后补充」通知**：普通追问（原咨询未退回）不通知审核律师，避免刷屏。
2. **每条补充只发一次**：幂等键按新咨询 id，重复提交不会重复通知。
3. **覆盖率依赖词面重合**：追问的 attribution 与首次咨询同算法（词典匹配），不是语义判定；没有重叠时为 `—`。
4. **不通知案件客户**：收件人仍是组织审核律师。
5. 通知失败只记日志，不影响追问结果与对比数据。

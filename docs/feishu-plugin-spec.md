# 飞书插件需求规格（#76 冻结版，2026-09-01）

> 场景池 14 条（docs/feishu-plugin-scenarios.md）→ 需求规格。**10 月开发立项输入**。
> 状态：M1（单聊咨询 + 法条核对）与 M2（合同初筛 + 文件解析）核心管线已于 2026-08-05 完成（app/services/feishu_service.py）；
> 出站待企业自建应用凭据接入；M3/M4 按 10-11 月立项推进。
> 原则：后端零新功能——全部复用现有 API，飞书端只做适配层（卡片/回调/文件上传）。

## 1. 范围与里程碑

| 里程碑 | 内容 | 场景 |

| M1（10 月首周）| 单聊咨询卡片 + 法条核对（只读） | 1、5 |

## 2. 需求规格（M1-M3，API 依赖映射）

### S1 群内即时咨询（场景 1）
- 触发：飞书群 @插件 + 文本 / 转发消息
- 产出：卡片含 分类/风险等级/置信度/法条引用（可点核对）/待补充事实/追问入口
- API：POST /api/legal/consultations（ConsultationIn）；GET 引用用卡片链接跳 web 引用弹窗
- 鉴权：企业内绑定（user_id ↔ 飞书 open_id，管理员开通）

### S2 合同风险初筛（场景 2、8）
- 触发：群发 .pdf/.docx → 插件下载解析
- 产出：风险条款卡片（风险列表/等级/原文摘录/修改建议）+ "深度审查"按钮
- API：复用 document 解析（POST /api/documents/parse 或现有上传流）→ POST /api/legal/contract-reviews
- 限制：单文件 ≤20MB，与 web 同限

### S3 文书生成（场景 3、4）
- 触发：场景模板（劳动仲裁申请书等）卡片表单
- 产出：草稿卡片，缺失字段【待补充】标注，律师补全后导出 PDF（web 端完成）
- API：POST /api/legal/drafts；续写走追问

### S4 审核队列（场景 9、14）
- 触发：风险等级 high 或需人工审核 → 卡片推送"有 N 份待审核"
- 动作：卡片按钮 通过/退回（原因必填）→ 回写
- API：POST /api/legal/approvals 或 review-actions（对齐 AI-2 回流，review_actions 落库）
- **价值**：降低律师审核成本 → AI-2 回流数据密度上升

## 3. 平台侧依赖（M5 前置）

| 依赖 | 现状 | 动作 |
|---|---|---|
| 企业绑定表（open_id ↔ user_id） | 无 | M1 前新增迁移（飞书授权回调落库） |
| 回调安全 | webhook HMAC 模式可复用 | 复用 tasks/__init__.py 签名校验 |
| 飞书开放平台应用 | 未申请 | 10 月申请企业自建应用（需企业管理员） |
| 文件上传限制 | web 端已有 | 对齐 |

## 4. 验收标准

1. M1 咨询卡 5 分钟内出结果（与 web 同链路，无额外时延）
2. S4 回填决策与 web 审核队列实时一致（同一 review_action 表）
3. 权限：非组织成员禁止调用（复用 verify_org_member_access）
4. 埋点：插件来源请求计入既有 llm_observability（不新建成本轨道）

## 5. 风险与决策点

- 场景 6/7（期限提醒、门户轻触达）依赖试点验证"案件闭环"留存价值——**M4 前用试点数据决策**
- 场景 10（私域知识库）依赖 KB 能力对齐——M4 评估，可能砍到 web 端
- 上架策略：先"企业自建应用"内测（10 家试点所免费），再开放平台上架（12 月商业化）

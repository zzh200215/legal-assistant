# 等保二级 POC 阶段自评（草案）# 合规 5.3 交付

> 依据：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》第二级；参照 GB/T 28448-2019《测评要求》自评。
> 范围：律智检 SaaS 平台（应用 + 数据面）。云基础设施（物理/虚拟化/网络）安全责任由云服务商（阿里云）分担，自评按"继承 + 应用责任"口径标注。
> 结论：POC 阶段按"自评 + 材料备查"应对审计；**正式商用前完成正式等保二级测评**。
> 关联：compliance-dossier §7.4。

## 2. 各控制点自评明细

### 2.1 安全物理环境（继承阿里云）

物理位置选择、访问控制、防盗窃防破坏、电力/温湿度、防水防火防雷等由云服务商保障，通过云服务商合规认证（等保/ISO）覆盖。POC 审计时出示云服务商合规证明。

### 2.2 安全通信网络

| 控制点 | 自评 | 实现/位置 |
|---|---|---|
| 通信传输加密 | ✅ | 全站 HTTPS/TLS（FastAPI/反向代理）；JWT 令牌鉴权（app/core/auth.py） |
| 身份鉴别 | ✅ | 密码 bcrypt 哈希存储；客户门户 OTP 一次性验证码 + X-Portal-Session 会话（legal_portal_api.py） |

### 2.3 安全区域边界

| 控制点 | 自评 | 实现/位置 |
|---|---|---|
| 边界防护 | 继承 | 云安全组/防火墙由部署方配置 |
| 访问控制 | ✅ | 角色四级（admin/reviewer/editor/client）+ required_roles 接口校验；资源级 verify_resource_access（app/core/auth.py） |
| 登录失败处理 | ✅ | 5 次失败锁定 30 分钟（LOGIN_MAX_FAIL_COUNT/LOGIN_LOCK_DURATION_MINUTES） |
| 安全审计 | ✅ | 登录/管理/操作双轨日志（admin_audit_logs + operation_logs） |

### 2.4 安全计算环境

| 控制点 | 自评 | 实现/位置 |
|---|---|---|
| 身份鉴别 | ✅ | 密码强度校验 + 哈希存储；OTP 锁定 |
| 访问控制 | ✅ | RBAC + 资源级鉴权 + 门户按组织隔离 |
| 数据完整性/保密性 | ✅ | 敏感字段 AES-256-GCM 静态加密（EncryptedText，独立密钥）；LLM 出站 PII 脱敏；出站邮件 DLP |
| 数据备份恢复 | 🟡 | 备份脚本 scripts/create_pilot_backup.py（MySQL/PostgreSQL 逻辑备份 + 数据目录打包 + SHA256 校验）；**已接入 celery beat 每日 02:00 全量调度（app/tasks.create_pilot_backup_task）+ BACKUP_OFFSITE_DIR 异地副本步骤（config 门控）+ BACKUP_RETENTION_COUNT 保留策略（默认保留最近 7 份，清理更旧，2026-08-05）；正式异地存储/增量待部署侧** |
| 入侵防范 | 🟡 | 速率限制/配额治理（LLM 日限 + 网关）；无主机级入侵检测/杀毒（差距，依赖云平台基线） |
| 剩余信息保护 | ✅ | 注销匿名化抹除主体字段；日志掩码策略见 SLA |
| 恶意代码防范 | ⬜ | 应用层无终端杀毒需求；服务器端由云镜像基线/托管安全承担（差距标注） |

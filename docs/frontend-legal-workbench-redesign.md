# LegalTech 前端重构蓝图

## 信息架构

```text
法律工作台
├─ 工作台       今日待办、最近案件、近期活动
├─ 案件         案件列表 → 案件详情
│  └─ 案件内工作 概览 / 文档 / 咨询 / 审查 / 文书 / 审核 / 任务 / 日期
├─ 文档         全部案件材料、合同与证据
├─ 法律研究     法规、案例、合同模板、文书模板
├─ 审核         待我审核、我发起的、已完成
└─ 任务         协作事项与处理进度

管理中心（按权限显示）
├─ 系统 / 组织 / 策略 / 计费
├─ Agent / 模型
└─ 评测 / 审计
```

技术能力仍保留在既有路由和 API 中，普通工作区不以 Agent、RAG、模型或工具调用组织导航。

## 导航结构

```text
工作台
案件
文档
法律研究
审核
任务
────────
管理中心
  系统 · Agent · 评测与审计 · 计费
```

现有 `/legal-workspace`、`/documents`、`/tasks`、`/agent`、`/system` 等路由保持兼容；新的工作区状态通过 `view`、`case_id`、`tab` 查询参数表达。

## 案件页面

案件详情以 Matter 为容器，头部展示案件名称、状态、负责人、客户、对方当事人和最近更新时间。主体分为：案情摘要、最近活动、待处理事项、关键文档、案件工作流和关键日期。咨询、合同审查、文书和审核是案件内工作动作，不再与案件并列。

## 合同审查线框

```text
合同名称 · 案件 · Version 2                    导出  提交律师审核
──────────────────────────────────────────────────────────────
合同原文（段落可定位、高亮）       │ 风险与问题
第 1 段 ……                         │ 高风险 付款条件不明确
第 2 段 ……                         │ 原文摘录 / 风险说明
第 3 段 ← 高亮                    │ 修改建议
第 4 段 ……                         │ 法律依据 · 版本
                                   │ 通过 / 退回 / 继续处理
──────────────────────────────────────────────────────────────
版本记录 / 历史审查 / 合同版本对比
```

复用既有 `source_location.paragraph`、`snippet`、法源版本和重提交流程；点击风险会定位原文，提交律师审核走统一审核队列。

## 文书线框

```text
左侧：文书类型、事实字段、待补充字段
右侧：可编辑正文、引用依据
底部：保存版本 / 生成 / 导出 / 提交审核
```

正文始终由用户编辑。AI 只负责草稿生成、事实缺口提示和内容建议；保存使用既有版本 API，并保留旧版本。

## 审核线框

```text
案件信息 → AI 分析结果 → 问题与风险 → 证据 / 法源 → 审核决定

左侧审核队列                         右侧审核对象
类型 / 标题 / 状态 / 时间             原文、风险、法源、批注与历史
                                     [通过] [退回补充] [转线下]
```

页面表达“AI 提供建议，人做最终决定”，审核动作和批注继续使用现有审核 API。

## Design System

| 层级 | 约定 |
| --- | --- |
| 页面 | `#F5F7F9` 背景，白色内容区，最大宽度 1480px |
| 文字 | `#202A35` 主文字，`#4B5968` 次文字，`#687787` 辅助文字 |
| 操作 | `#315F91` 主色，仅用于当前项、链接和主要动作 |
| 边框 | `#DCE2E8`，1px；层级优先靠分隔线与留白 |
| 圆角 | 4–8px，避免气泡和营销卡片感 |
| 风险 | 红表达高风险，琥珀表达中风险，绿表达低风险；不用于装饰 |
| 组件 | `CaseHeader`、`LegalDocumentViewer`、`RiskIssueItem`、`EvidenceReference`、`ReviewTimeline`、`DocumentVersion`、`MatterActivity` |

页面结构优先使用文档分栏、列表、时间线、版本和审核动作；普通用户不显示检索算法、模型路由和 Agent 实现细节。

## 当前实现进度

第一阶段已完成工作台导航、案件容器、合同审查双栏、文书编辑和律师审核工作流。

第二阶段已完成资料库阅读器和案件助手。资料库首屏以搜索、目录、正文和法源元数据为主；导入、编辑和状态维护收进维护区。案件助手复用现有 WebSocket 流式能力，使用 `case_id` 校验权限并注入案件摘要上下文。

第三阶段已加入管理中心入口，将系统、自动化、评测审计、策略、组织和计费按管理员工作流分组；原有系统标签和 Agent 路由继续兼容。案件内咨询、合同、文书和审核队列支持服务端案件过滤，避免跨案件历史混入。

## P1 进度

文书工作区已补齐版本操作：案件进入文书页后自动打开最新草稿，用户可从版本记录选择历史快照，并在正文下方查看历史版本与当前编辑内容的增删 Diff。历史版本继续复用既有 `listDraftVersions` 与版本快照 API，未新增数据库结构。

审核工作区已完成案件上下文与队列排序：审核条目返回 `created_at`、案件标题和案件状态，队列跨咨询、合同审查、文书统一按最近提交时间排序；审核详情先展示所属案件，再展示 AI 分析、风险、法源、批注和最终决定。审核状态机与原有审核 API 保持兼容。

P1 验收：文书版本、审核工作流和资料库阅读器均已接入案件过滤、历史留痕和现有 API。前端 `npm run build`、`npm run lint -- --quiet` 与后端法律工作区单元测试通过。

## P2 进度

客户门户的聚合链接、品牌配置和访问指标已有后端能力。本阶段补上管理侧运营视图：案件门户页显示生效链接、3 天内到期链接、累计访问和最近访问时间，并在链接列表中保留最近访问记录；新增受案件权限保护的 `/portal-analytics` 聚合接口，提供周期访问趋势、去重访客、拒绝访问和链接表现，前端以趋势区呈现。接口只返回聚合值，不暴露访问日志或访客标识。

## P3 进度

客户门户账单已从单张摘要升级为完整对账：服务端返回案件下全部非草稿发票、明细项目、已确认收款、待收余额和总览汇总；旧版 `invoice` 字段继续保留兼容。门户前端展示账单总额、已收、待收、发票状态、账期、明细和收款记录；不下发客户联系方式、支付流水号、内部备注或操作人信息。

## P4 进度：Matter 领域统一

- 新增 `MatterService` 门面，统一案件权限、案件摘要、工作产物和活动时间线读取。
- 新增 `/api/legal/matters/{case_id}/summary`、`/artifacts`、`/activity` 只读接口。
- 案件创建、案件更新、咨询、合同审查、文书、审核动作和批注会写入 `matter_activities`；活动只保存脱敏元数据和短摘要。
- 案件摘要中的待处理任务使用 `workflow_runs` 状态统计，避免跨案件混入历史任务。
- 旧版 `case_id` 可选接口继续兼容，新接口以案件为强上下文。

## P5 进度：工作流运行与事务 Outbox

- 新增 `workflow_runs`、`workflow_events`、`workflow_outbox_events` 三张表。
- Celery 已注册任务通过信号自动创建运行记录，并在成功、失败、重试时追加状态事件。
- 运行记录支持案件/组织范围查询、事件历史、进度、重试次数、checkpoint 和取消状态。
- 新增 `/api/tasks/workflows` 查询接口和取消接口；查询强制组织范围，案件运行再次校验案件权限。
- 取消采用协作式终止：排队任务直接进入 `cancelled`，运行中任务先进入 `cancelling`，worker 在阶段边界确认取消后写入终态；Celery revoke 仅作为加速信号，数据库状态是最终依据。
- `task_runs` 同步记录 `cancelled` 终态，成功/失败信号不会覆盖已请求取消的工作流；重复取消保持幂等，不重复追加取消事件。
- Outbox 由独立任务按租约领取，通过 Redis 发布 `legal.workflow.events`，事件历史继续保留用于回放。
- 新增租约回收任务，避免 worker 中断后事件永久停留在 `sending`。
- 迁移版本：`20261003_0089_matter_workflows`。

## P6 进度：工作流状态产品化

- 新增 `WorkflowRunsPanel`，将排队、执行中、取消中、已完成、失败和已取消统一呈现为案件工作流状态。
- 案件概览和案件任务页展示当前案件的执行进度、当前步骤、最近更新时间与事件时间线；任务中心支持显示全组织最近工作流，并可沿用 `case_id` 筛选。
- 用户可以从面板查看工作流事件详情并取消可取消的运行；取消仍由服务端数据库状态作为最终依据，前端只提供协作式终止入口。
- 轮询只在存在活动运行时启用，组件卸载时清理定时器，不建立新的实时连接；原有任务看板、任务详情和旧任务 API 保持兼容。

## P7 进度：工作流接口契约与权限加固

- 工作流路由在通用任务动态路由之前注册，避免 `/api/tasks/workflows` 被旧任务详情路由按整数参数拦截。
- 单条工作流查询和取消要求当前用户具备组织上下文；案件工作流继续执行案件成员校验，跨组织和跨案件请求统一隐藏为 404。
- 取消接口对已取消状态保持幂等，不重复撤销 Celery 任务或追加事件；成功和失败终态仍返回不可取消的 409。
- 新增 FastAPI 集成测试覆盖组织隔离、案件权限、无组织用户、重复取消和终态保护。

## P8 进度：Outbox 运维闭环

- 工作流事件投递失败会释放租约并回到 `pending`，按有限指数退避重试；达到上限后进入 `failed`，避免毒性事件无限占用队列。
- 缺失工作流或事件的异常 Outbox 记录会直接标记失败并保留错误摘要；租约过期记录仍由回收任务重新入队。
- 投递任务返回 `delivered`、`retried`、`failed` 三类摘要，事件正文继续通过 Redis 发布，数据库事件历史保持可回放。
- 新增投递成功、发布异常、毒性事件和租约回收测试，覆盖 worker 中断与 Redis 不可用时的恢复路径。

## P9 进度：管理中心工作流运行视图

- 管理中心的系统任务页新增组织级“案件工作流运行”区，支持全部、进行中、失败和已取消筛选。
- 运行摘要展示当前执行、失败和取消中的数量；列表展示案件动作、当前步骤、进度和最近更新时间，并保留取消入口。
- 视图复用现有工作流查询与取消 API，管理员入口按既有系统权限保护；普通法律用户继续只在案件上下文中看到自己的工作流。
- 管理视图只呈现业务状态和错误摘要，不暴露 Redis、Outbox、Agent 或模型实现细节。

## P10 进度：工作流运营统计口径

- 新增管理员专用 `/api/analytics/workflows/overview`，按组织和时间窗口聚合运行状态与 Outbox 投递状态。
- 管理中心摘要使用服务端聚合的执行中、失败、取消中和待发布事件数量，不再用前端最近 100 条记录推算总量。
- 接口不返回任务正文、提示词、模型参数或事件载荷；普通用户没有访问权限。
- 集成测试覆盖管理员权限、组织隔离、运行状态和投递摘要。

## P11 进度：工作流审计下钻

- 管理中心工作流运行列表支持打开单条运行详情，查看状态变更时间线、当前步骤和失败摘要。
- 详情继续复用 `/api/tasks/workflows/{workflow_id}`，按组织和案件权限过滤；前端不展示事件载荷、提示词或模型信息。
- 关闭详情不会改变运行状态，取消动作仍走既有幂等取消接口。

## P12 进度：工作流终态通知

- 工作流完成、失败或取消后，为发起用户创建站内通知；通知使用幂等键，重复 Celery 信号不会重复出现。
- 通知只保存案件动作摘要和案件引用，正文、提示词、模型参数及事件载荷不会写入通知。
- 通知铃铛支持查看摘要、标记已读，并回到对应案件或任务上下文。
- 通知创建失败不会阻断任务终态写入；既有通知 Outbox 负责后续站内投递。

## P13 进度：工作流通知深链

- 工作流通知携带运行标识，点击后可直接打开对应的工作流详情和事件时间线。
- 案件通知回到案件任务页，并保留 `workflow_id` 和案件上下文；没有案件引用的通知回到全局任务中心。
- 案件页和全局任务页均支持从 URL 参数自动选中运行，刷新页面后仍可恢复定位。
- 深链只暴露运行标识和案件标识，不在 URL 或通知正文中携带任务正文、提示词、模型参数或事件载荷。

## P14 进度：失败工作流重试

- 失败的文档解析、切分、索引和开放合同审查支持从案件任务页或管理中心重新投递。
- 重试不会覆盖原失败运行；原记录追加 `workflow.retry_requested` 审计事件，新 Celery 任务启动后自动形成新的工作流运行记录。
- 重试接口继续执行组织、案件和业务对象权限校验，并拒绝运行中、已完成、已取消或不支持恢复参数的工作流。
- 前端只展示“重试”业务动作，不暴露 Celery 任务参数；成功后刷新工作流列表，失败时保留原错误上下文。

## P15 进度：独立通知中心

- 通知列表接口支持未读/已读、案件、通知类型和分页筛选；原有 `items` 与 `unread` 字段继续兼容顶部铃铛。
- 新增通知中心页面，提供筛选工具栏、未读计数、批量已读、分页和单条深链跳转。
- 顶部铃铛保留最近通知快速预览，并增加“查看全部”入口；工作流通知继续回到案件任务或全局任务上下文。
- 通知查询始终按当前用户隔离，不返回失败投递记录，也不新增正文、模型或技术载荷。

## P16 进度：案件文档关联

- 文档列表接口新增 `case_id` 范围过滤，并返回案件归属和资料类型元数据；过滤在数据库查询层完成，避免客户端拉取全库后再筛选。
- 案件文档页新增合同、证据、法规、案例分类视图，材料列表显示版本、状态和更新时间。
- 点击案件材料进入现有文档阅读工作区，并保留案件上下文；从文档工作区可返回案件。
- 未改变文档权限模型，案件过滤仍叠加当前用户、组织、部门和文档访问规则。

## P17 进度：审核任务分配与超时

- 咨询、合同审查和文书审核对象新增审核截止时间，审核队列返回负责人和是否逾期。
- 组织管理员或审核律师可以将待审对象分配给同组织的审核律师/管理员，也可以取消分配；重新提交内容会清除旧负责人和截止时间。
- 审核页面新增负责人、截止时间和逾期状态操作，审核决定、批注和历史时间线保持原流程。
- 新增审核人列表和分配接口；定时任务扫描逾期审核并向负责人发送幂等站内提醒，提醒正文不包含技术载荷。

## P18 进度：文书协作与版本恢复

- 文书编辑器支持自动保存，顶部显示待保存、保存中、已保存、冲突和失败状态；自动保存不制造版本噪音。
- 自动保存和手动保存版本均携带 `row_version`，服务端在过期编辑提交时返回 409，避免静默覆盖他人修改。
- “保存版本”会固化正文与左侧事实字段快照；历史版本支持 Diff 和恢复，恢复前内容会继续写入 `restore` 快照并生成新的业务版本。
- 新增文书编辑接口：`PATCH /api/legal/drafts/{id}/autosave`、`POST /api/legal/drafts/{id}/versions`、`POST /api/legal/drafts/{id}/versions/{version_id}/restore`。
- 既有退回补充事实后的重新提交接口保持兼容；已定稿、归档和线下终态文书不能直接自动保存或恢复。

## P19 进度：文书协作深化

- 版本保存支持版本说明；版本记录同时保留正文、事实字段和说明，便于律师回溯修改意图。
- 文书工作区支持任意两个历史版本的服务端 Diff，前端可分别设置对比起点和终点。
- 新增正文批注：支持绑定版本与行号范围、记录作者、标记已处理/重新打开，批注不会随着正文覆盖而丢失。
- 文书头部显示最近更新时间、当前版本和参与者列表，协作者包括负责人、审核人和批注作者。
- 新增接口：协作状态、批注列表/新增/状态更新、任意版本 Diff；权限沿用文书负责人、指定审核人和管理员范围。
- 迁移版本：`20261006_0092_document_collaboration`。

## P20 进度：合同审查闭环

- 合同原文支持风险定位到具体段落和字符范围，风险条款片段保持高亮，点击风险后同步滚动到原文。
- 风险详情支持展示修改建议，并可将建议加入修订稿参考；修订稿统一走下一审查版本，保留原始审查记录。
- 结构化风险项支持接受、已修改缓释和忽略三种律师处理动作，组织审核律师与管理员均可操作。
- 合同历史版本支持分别设置对比起点和终点，并在审查页直接查看两版正文 Diff。
- 退回修订、重新审查、风险项处置和律师审核动作在同一合同工作区闭环，原有风险证据、法源和版本留痕继续保留。
- P20 未新增数据库表，复用现有合同审查版本、结构化风险项和审核状态机。

## P21 进度：审核运营增强

- 审核队列支持关键词、状态和逾期筛选，服务端先过滤再返回，避免前端拼装运营口径。
- 支持批量分配审核人、批量通过和批量退回；单条审核状态机、幂等写和案件权限继续生效。
- 审核页头部新增 SLA 摘要：待处理、逾期、未分配和平均处理小时数。
- 组织审核律师可以查看本组织审核队列、执行审核动作和查看审核统计；系统管理员与部门管理员保持兼容。
- 逾期率、截止时间覆盖率、分配覆盖率和平均处理时长由服务端统计，不依赖前端最近列表推算。

## P22 进度：案件助手产品化

- 案件助手侧栏显示当前案件摘要和咨询、审查、文书、待审数量，数据来自案件摘要接口并沿用案件权限校验。
- 助手消息提供面向案件工作的快捷动作：形成咨询摘要、准备文书草稿、整理下一步任务和关键日期。
- 引用卡片支持回到案件资料库；有 `document_id` 时直接打开对应文档，否则回到案件法律资料视图。
- WebSocket 协议保持兼容，`case_id` 继续由服务端校验并注入案件上下文；通用无案件对话仍可使用。

## P23 进度：法律资料库增强

- 资料库主视图收敛为“法规与案例 / 案件材料”两个业务范围，普通用户默认看到资料类型、效力状态、版本、适用范围和阅读正文。
- 法源阅读器支持收藏、关联当前案件、正文命中高亮、单份资料 Markdown 导出和搜索结果 CSV 导出；保留条文级阅读与引用位置。
- 案件材料复用文档权限和 `case_id` 查询，按合同、证据、法规、案例筛选，点击后进入现有文档阅读工作区并保留案件上下文。
- 收藏和案件关联使用服务端持久化模型：`legal_source_favorites`、`legal_case_sources`，接口沿用 `/api/legal/sources` 路由族并执行用户/案件访问校验。
- 资料导入、编辑、状态维护和检索评分仍可用，但默认收进“资料维护”折叠区，避免技术检索细节成为普通法律用户的主界面。
- 迁移版本：`20261006_0093_legal_library`。

## P24 进度：文档工作区产品化

- 文档首屏改为“法律资料 / 文档”语义，案件上下文、资料总数和当前处理摘要优先展示。
- 文档目录统一使用法规、司法解释、案例、合同模板、文书模板等业务分类，减少技术枚举值对普通用户的干扰。
- 知识库权限和问答参数改为默认收起的高级设置；处理记录只有存在内容时才显示，避免 Agent/执行细节成为主工作流。
- 当前文档操作改为“继续处理 / 重新处理 / 提取待办”，文档助手保留引用回答和反馈闭环。
- 不改变文档列表、解析、问答、版本、下载策略和任务 API；仅调整产品层级与展示语言。

## P25 进度：工作台首页产品化

- `/legal-workspace` 在没有明确 `case_id` 时显示真正的工作台首页，不再自动打开第一条案件。
- 首页展示进行中案件、待审核、咨询和合同审查摘要，并提供最近案件、待处理审核和常用入口。
- 用户从最近案件或快捷入口进入具体案件后，才进入 Matter 详情和案件内工作流；`case_id`、`tab`、`view` 查询参数继续兼容既有深链。
- 待审核数据复用既有 `/legal/review-queue` 接口，案件列表复用既有案件接口，没有新增后端模型或路由。

## P26 进度：任务中心产品化
